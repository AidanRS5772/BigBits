## Architecture

BigBits is a big-integer/big-float library optimized with inline assembly (x86-64 and ARM64) and adaptive algorithm selection.

### Layer structure

```
src/utils/       ← raw buffer arithmetic (Vec<u64> limb arrays)
src/tuning/      ← performance knobs: schema, resolver, tuning-file format, generated accessors
build.rs         ← generates the knob accessors from src/tuning/schema.rs, the target's preset and the machine's own file (BIGBITS_TUNING)
presets/         ← per-target tuning files written by `cargo tune tune --write-preset` (aarch64.toml: the M1's tune, for every aarch64 target since 2026-11-13, when the user had it renamed from aarch64-macos.toml, the name older entries here and in the docs use), and local.toml, this machine's own tune (gitignored; .cargo/config.toml points BIGBITS_TUNING at it)
src/bit_nums/    ← ergonomic number types wrapping utils
src/tests/       ← test suite (gated by #[cfg(test)] in lib.rs)
benches/         ← Criterion benchmarks
```

### Utils layer (`src/utils/`)

All algorithms operate on little-endian `u64` limb buffers (index 0 is the least significant limb). Dynamic entries use pooled `Vec<u64>` scratch storage; static entries use caller-selected `[u64; N]` stack storage.

- **`mul.rs`** — Multiplication with dynamic dispatch: schoolbook → Karatsuba → FFT (via `rustfft`) → NTT. Assembly primitives (`mul_prim_asm`, `mul_asm_x86`, `mul_asm_aarch`) handle 64×64→128-bit multiply. Also provides high/middle-product variants (`hi_mul_buf/dyn/static`, `mid_mul_buf/dyn`) that compute only a limb-range of a full product — these back the Newton-Raphson reciprocal refinement in `div.rs`. Every middle-product entry accepts exactly `long[2n-1] × short[n] → out[n]`; callers materialize any required low zero padding before invoking it. `ntt_mid_mul_static` also accepts a `long` that passes `N` by low zero limbs (a reciprocal's padded divisor window): `long = T·B^z`, so it convolves `T` at the unchanged transform size and reads the band `z` coefficients lower, bit-identical to the dynamic product. Both NTT middle products size each prime's transform for at least `2n+1` coefficients (`mid_ntt_size`): the accumulation reads two coefficients below the band, which no wrapped column may reach. Static NTT entries handle transforms larger than `N` (non-5-smooth `N`) via `ntt_chunked_convolution`, which emulates the declared transform size with rescaled sub-transforms clamped to `N`. `sqr_mod_bnm1_dyn(a, out)` squares mod B^m − 1 (m = `out.len()`, a.len() ≤ m) into the canonical residue in [0, B^m − 1). With m from `bnm1_size(min)` (the smallest m ≥ min whose 4m 16-bit digits are an FFT length, o·2^a with o in {1, 3, 5, 7, 9}), and a of more than `mul.sqr_bnm1_fft` and at most `FFT_BNM1_16BIT_CUTOFF` limbs (`bnm1_fft`), it is one cyclic FFT (`fft_sqr_mod_bnm1`: `fft_sqr_entry` without the zero padding, so the transform wraps at exactly B^m and its top carry folds to the bottom), half the transform of a full square; otherwise `sqr_dyn` and a fold. `FFT_BNM1_16BIT_CUTOFF` (57344 modulus limbs, a `bnm1_size`) is its dispatch limit. Dynamic only; there is no NTT or static version. FFT lengths come from `find_fft_size(n)`, the smallest 4·o·2^a at or above n with o in {1, 3, 5, 7, 9}: rustfft's NEON planner runs only 2^k and 3·2^k through radix-4, so other sizes cost 1.2–1.9× per point, and those outside this set lose to a slightly longer cheap one (0.69× for products and 0.71× for squares against the old smallest 7-smooth size, on the M1; `docs/fft_precision.md`). `recombine` and `sqr_recombine` read `fft_twidles(n)`, one exact `cis` table per transform size, cached per thread beside the plans in `FFT_CACHE`, and on aarch64 take two conjugate pairs per NEON step with fused products (x86 stays scalar). `scale_and_round` multiplies by 1/n at power-of-two lengths, bit-identical to the division any other length keeps, and `fft_accumulate` reads only the one limb past `out`. Operands go in as balanced digits in [−2^15, 2^15) (`balance_limb`, `decompose`, `sqr_decompose`), which makes a coefficient's digit products cancel and reads about 35–300× lower on random and high-digit operands, at no measurable cost. An operand's top digit stays unsigned, at most 2^16 (`fft_absorb_top_carry`), so no transform grows; `fft_accumulate_signed` carries the signed coefficients; and middle products no longer add `middle_correction`, as the band already holds the value to about 2^34 units of its lowest limb, so compare them by value, since that can flip a run of zeros or ones. Every 16-bit FFT entry reads its own rounding: `scale_and_round` returns the call's `FftRounding`, whose `err` is the largest distance between a coefficient and its rounded integer. A call past `FFT_FOLD_TRIGGER` (0.25) runs the fold check (`fft_fold_agrees`) on all N rounded coefficients and is redone on the NTT only if that fails (`ntt_entry_dyn`, `ntt_sqr_entry_dyn`, `ntt_mid_mul_dyn`, and for the cyclic square a full NTT square folded mod B^m − 1), outside the `FFT_CACHE` borrow; `fft_reroutes()`, `fft_fold_checks()` and `fft_fold_reroutes()` count them. A high reading alone isn't a redo, as most such results are right. A wrong limb needs a coefficient off by more than 0.5, reading 1 − e, so a wrong result skips the check only with one off by at least 0.75 and every other within 0.25. The check tests V = a·b mod a prime, where V sums the coefficients at their digit positions. Products and squares take `FFT_FOLD_PLAIN`, the largest safe prime below 2^64 / 5, whose weights don't repeat within any transform. Middle products and cyclic squares wrap, so their prime must divide 2^(16N) − 1, one per size in `FFT_FOLD_WRAPPED` (N from 65536 to 524288; other sizes redo on the NTT): at least 40 bits with weights repeating every N/16 digits or fewer, because a rounding wave leaves wrong coefficients at evenly spaced crests, which pass primes repeating at N, N/2 or N/4 9–28% of the time, against 0 of 446 for this table. They still pass errors repeating at a period no repeat divides (seen past the limits), opposite errors a repeat apart and equal ones half a repeat apart. There's no coefficient gate: a balanced coefficient stays under 2^48 at every dispatch limit (a compile-time assert in `mod.rs`), so readings stay fine enough, and past each dispatcher's largest transform a checked entry goes straight to the NTT without a transform. So the limits bound soundness as well as speed. `fft_entry` and `fft_sqr_entry` then check the result by residues (`verify.rs`) and redo a mismatch on the NTT, also counted in `fft_residue_reroutes()`, which should stay 0: always in debug builds, and in release when `FFT_RESIDUE_CHECK` (`mod.rs`) is set. It is off by default, as it costs 2.55 ns per limb of operands and result: 20% of the FFT at 256 limbs, 12% at 16384, 5.6% at the product limit. The crate-internal `fft_entry_checked`/`fft_sqr_entry_checked` take the fold check as a flag, so the tests can reach the residue check. Middle products and cyclic squares have no residue check. The doc-hidden `fft_entry_raw`, `fft_sqr_entry_raw`, `fft_mid_mul_raw` and `fft_sqr_mod_bnm1_raw` redo nothing and return the `FftRounding`, fold verdict included, beside the result, for the probe and the tests. On the same 35112 reachable worst-case calls, unsigned digits with the old 0.4 limit and gate gave 2527 wrong results, 0 missed and 6727 NTT redos, and balanced digits with the fold check gave none wrong, 0 missed, no redos and 412 needless fold checks, all on balanced worst-case patterns; random limbs never fire. Under Rosetta (SSE) a few worst-case middle products inside the limits do go wrong, so that's a NEON result, and AVX2 is unmeasured. Release A/B: 0.995× over 13 operations against the tree before these, with a worst point of 1.018×. The four limits in `mod.rs` are `FFT_16BIT_CUTOFF` (131066 output limbs), `FFT_SQR_16BIT_CUTOFF` (65533 operand limbs) and `FFT_MID_16BIT_CUTOFF` (65533 short limbs), the largest the 2^48 assert allows, all on the 2^19-digit transform, and `FFT_BNM1_16BIT_CUTOFF` (57344 modulus limbs, the largest `bnm1_size` below 64800, where random operands in unsigned digits tripped the old check 2^-10 of the time at the old sizes; the next one, 65536, fails the assert). With random operands the FFT beat the NTT at the first three by about 4× on one thread and 1.3–2× against the NTT on the default 8-thread pool; past them the pool's NTT ties or wins at some sizes (`benches/probes/fft_sizes.rs`, `docs/fft_precision.md`). Products and squares haven't been swept with worst-case operands on their new 524288 transform. In debug builds `mul_dyn` and `sqr_dyn` also assert every NTT result against the residue verifier.
- **`div.rs`** — Division exposes standard quotient-only, quotient-with-remainder, reciprocal, and high quotient-only operations in dynamic and static allocation models. Quotient operations dispatch among Knuth, Burnikel-Ziegler, and Newton-Raphson; reciprocal operations dispatch directly between Knuth and Newton-Raphson and have no standalone Burnikel-Ziegler path. Forced algorithm entry harnesses live in `src/tests/test_div.rs` and `benches/`, where they compose the public preflight and prepared execution drivers; they do not live in the algorithm module.

  Division operands must be trimmed and `d` must be nonzero. Let `M = div_quotient_len(n.len(), d.len()) = n.len().saturating_sub(d.len())`. Standard `div`/`div_rem` require `q.len() >= M`, write the low `M`-limb quotient body, and return the possible structural limb at index `M`. When `q.len() > M`, that limb is stored in `q[M]`, the remaining tail is zero-filled, and the function returns zero, matching multiplication's overflow convention. Equal-width operands therefore permit an empty quotient body while returning their complete single-limb quotient. Quotient-only entries preserve both operands, and standard `div_rem` always leaves the exact remainder in `n`.

  High quotient entries `hi_div_dyn` and `hi_div_static<N>` preserve the high-window capability without a remainder variant. For `q.len() = K < M`, they return the same structural overflow and write body digits `M-K..M-1` into `q`; when `K >= M`, they delegate to standard division. High-window preflight drops irrelevant low numerator limbs and exact whole-limb divisor factors before the rigid backend. Newton-Raphson keeps its contiguous `K+1` internal quotient and bridges exact-width/high-window callers through pooled dynamic or `[u64; N]` static temporary storage; an output with an overflow slot is a direct fast path.

  Each standard call validates and prepares operands, dispatches using the logical quotient width `M+1`, and then runs a prepared driver with a quotient body of width `M`. Knuth returns its initial top estimate directly. Burnikel-Ziegler returns the top digit from its initial block while later blocks fill the body. Newton-Raphson retains its contiguous full-width core and BZ correctness fallback. Tests and benchmarks force `DivAlg` or `RcpAlg` through the same prepared drivers used by public dispatch.

  Reciprocal entries preserve `d`, and `rcp.len()` is the requested precision. For `D = d.len()`, `R = rcp.len()`, `B = 2^64`, and `X = min(floor(B^(D + R - 1) / d), B^R - 1)`, the returned approximation has numeric error strictly below `B`; the least-significant output limb is intentionally not guaranteed exact. Reciprocal drivers remove exact low-zero limb factors and retain only the high divisor window relevant to `R` (R + 1 limbs), so work does not scale with irrelevant low divisor limbs. Like every static entry, `rcp_static`/`rcp_prepared_static` assert that `d` and `rcp` each fit `N` limbs. The NR reciprocal attempt uses two internal low guard limbs and discards them, but omits the full `d * rcp` verification product and bounded final correction pass. The guard limbs and schedule parity put its work buffer and last divisor window up to 3 limbs past R; the static attempt keeps those two in `[[u64; N]; 2]` storage, caps its error bands at N (they stop a couple of limbs past p + 1), and relies on the window's limbs past N being zero padding, so static NR completes for every R ≤ N (only N ≤ 3 leaves no room for a band and retries Knuth). Division's upward-biased Knuth seed reuses `knuth_rcp_normalized` with seed 1 and an explicit increment; its quotient/remainder corrections remain exact.

  Burnikel-Ziegler still uses Knuth for its recursive base cases. Newton-Raphson division falls back to Burnikel-Ziegler when estimation or bounded correction fails; the prepared reciprocal driver falls back to Knuth when refinement or normalization cannot produce a usable approximation, or when a tiny static N leaves no room for an error band. These are correctness fallbacks, not top-level performance dispatch.

  The public dispatchers are `div_dyn`, `div_rem_dyn`, `hi_div_dyn`, `rcp_dyn`, and their static counterparts. Division selection measures the logical quotient width q (the body and its structural limb) and the effective rigid divisor width d after its exact low-zero limb factor. **Dynamic quotient entries compare fitted runtime equations per call** (`dyn_div_alg` → `dyn_div_alg_at`, with a `DivEq` and mul's `MulEq`, each read once; since 2026-11-11; `dyn_div_best` is the same choice with its predicted ns, which a series' finalize is priced by, and is `#[inline(always)]`: out of line it cost `div_dyn` 18 ns at 76/64), as the choice has two inputs: Knuth `a q d + b q + c d + e`; NR as its own products priced by tier (`DivEq::nr_parts`, since 2026-11-10): the reciprocal chain to h + 2 limbs (h = q / 2 + 1; from each precision p a middle product with a (p + 1)-limb short side and a high product into p limbs) and `nr_refine_quo`'s three (the numerator's top by the reciprocal into h + 2 limbs, the error band's middle product, the correction into l + 2 limbs), each put in the tier its dispatcher picks (`dyn_mid_dispatch_at`: schoolbook's n × n time below `mul.fft_mid`, the FFT's at `fft_mid_size(n)` from it; `hi_alg`: half a schoolbook product of the window up to `mul.dyn_partial_mul`, mul's prediction for the operands' tops above), with one fitted multiple a tier, `+ b q` (quotient only, NR's time has no term in d: it reads the divisor's top window), and with the remainder `+ r Mul(d, min(q − 1, d + 1)) + b q + c d`, the product `nr_rem_finish`'s. The school tiers are closed forms, so a small division's dispatch reads no product equation. Its first form, a multiple of M(h, h) (a full product's price), fitted at 4.2–4.7% because NR runs no Karatsuba: its residual swung ±7% between 90 and 720 quotient limbs; and BZ as its recursion: (q − 1) / d whole 2/1 blocks, each Σ 2^k M(d / 2^k) down to Knuth leaves (`bz_block_parts`: products and leaves), and a top block of `top` = (q − 1) % d + 1 quotient limbs that is either Knuth's equation or, on a padded numerator, a block priced by its quotient's significant pieces (`bz_padded_top_ns`): at the level with pieces of n limbs, min(top / n, 2^k) whole products M(n, n), one M(n, top mod n), nothing for the zero pieces above, and the leaves in full. That pricing is what `div_3_2` does since 2026-11-10: it multiplies each quotient piece at its significant width (`buf_len`) and skips a zero piece, where before every piece went through at its structural width and only the FFT entry, which trims its own operands, noticed the zeros (the fitted power `(top / d)^g` tried for that, `div.bz_ns_fill`, read 15.4% and is removed). BZ's fitted multiples came out at 0.99 and 1.00 on the M1 before that change: the recurrence over mul's and Knuth's equations is nearly exact. **BZ's equation was a marked problem and no longer is** (its section under "Marked problems" in `docs/tuning_implementation.md` keeps the four forms tried): every division fit, Knuth's unchanged one included, read 4.4–9.5% on 2026-11-10 while the machine was power-throttling, and the multiples 1.04, 0.99 and 0 ns per quotient limb were predicted from a drift-cancelled diagnostic. On a steady machine the tuner fits the form at 2.0–2.4%, and the M1 preset held its final thorough fit (1.044, 0.978 and 0, at 2.3%), and since 2026-11-11, with the term in q that had read 0 out of the form, 1.031 and 0.976 at 2.9% held out; the schema's defaults keep the predicted multiples. The tuner still treats BZ's and NR's forms as revised (`Fit::evidence_revised`: NOISY, not REJECTED, above the line). Dynamic BZ's own top-block choice compares the same two predictions (`dyn_bz_top_padded`, which the tune-only `BZ_TOP_FORCE` overrides for the tuner's forced timings); static BZ keeps `use_bz_for_top_block` (`use_bz_for_top_block_at` at an explicit leaf and scale), whose constant `div.bz_top_padded_cost_scale` is swept on the dynamic forced top-block timings (0.92 on the M1, losing 1–2% of measured time where 1.8 lost 3.7%; static values are approximate). The cheapest prediction among the algorithms that can take the shape wins: NR needs `nr_split`'s room (q ≥ 8), BZ a divisor past `div.bz` and a 2/1 block of its own (`bz_plan`: a whole block, q > d, or a top block predicted cheaper padded than Knuth), and Knuth always can. No equation is read where nothing else can run, nor where the measured tables `div.dyn_small` and `div.dyn_rem_small` name an algorithm (since 2026-11-12: rows by the divisor's limbs, change points over the quotient's, a cell Knuth, BZ, NR or "the equations"; `dyn_div_small`, and `sections::div::small_table` measures them by the rule on tables under "Tuning rules": every algorithm that can take the shape timed, forced, with the decision beside them, a row ending where the decision is within 5% of the division). On the M1 they hold only Knuth cells, 32 change points with rows of their own at divisors to 38 limbs (quotient only) and 57 at divisors to 108 (with remainder). They replaced `div.dyn_knuth_d`/`div.dyn_rem_knuth_d` (38 and 101), the widest divisor at which the equations picked Knuth for every quotient, which the tuner computed from them and which cost one compare at any quotient: the tables hand a division to the equations as soon as the rule allows, so 12 of the division grid's 40 shapes that the guards settled read the equations now and run 2.8% slower as a group (0.9% to 7.3%: `div_dyn` 40/32 the most), which the user accepted for the one rule's sake ("just accept it then it is within the noise threshold roughly anyway. (For the sake of consistency)"). The knobs are `div.knuth_ns_*`, `div.nr_ns_*`, `div.nr_rem_ns_*` and `div.bz_ns_*` (held-out rms in the M1 preset: 2.2%, 3.1%, 3.8% and 2.9%; under the method and the fuller forms before 2026-11-11 they fitted at 2.5%, 1.4%, 2.9% and 2.3% on their own grid), from `division_timings`' forced runs, each timing the division alone: a quotient-only probe copies nothing, and a probe with a remainder, which has to restore the numerator it overwrites, has that copy timed on its own and taken off (until 2026-11-10 every probe copied it, which was more than half of NR's quotient-only time at a short quotient over a long divisor and put that fit at 5.1%). Since 2026-11-11 the shapes are (q, d) scattered over 4 to 4096 limbs each, every other one held out, timed by `measure::time_fit` (see "How a fit is found"), and a tune times only what the fits read (Knuth, NR and BZ's two forced top blocks). **A fit takes the shapes its equation is read for** (since 2026-11-12, the user's rule: "it is just good practice to not fit over samples that the fits arnt used for"): a tune fits the four equations on every shape first, measures the two tables under that fit, then fits them again from the same timings (`sections::div::tune_late`, `Rows::Read`), NR's and BZ's without the shapes the entry's table names an algorithm for (`read_for`), where no decision reads them. Knuth's keeps every shape: its equation is also a price inside BZ's (the leaves, a Knuth top block) and inside a series' finalize, read at any size. `cargo tune division` times every algorithm and the entries on shapes no tune takes and reports the measured time the equations' picks and the entries lose on the half held out (under the old half-step grid: 0.02% for `div_dyn`, worst 1.5–6%; 0.15–0.18% for `div_rem_dyn`, worst 15%, where NR with a remainder is picked at a short quotient over a divisor past 1200 limbs). In the second pass the divisor sits 13 limbs further into its allocation than the numerator does, so the two passes differ in where the one lies against the other: Knuth by a 1024-limb divisor runs up to 2.45× slower on the M1 with the divisor 1 to 7 limbs past a 4096-byte alignment against its working buffer (its loads alias the numerator's stores; a property of the library's loop, not looked into), and with one placement a tune's fits twice came out with one shape 50–75% off. Each fit's evidence names the shape of its worst residual. They replaced the hand-fitted BZ-vs-NR cutoff rule, which lost 0.8% of measured time on `div_dyn` (worst 37%) and 3.4% on `div_rem_dyn` (worst 59%) against the equations' 0.03% (4%) and 0.15% (14%); in a normal build the 40-shape division grid of `benches/tuning_bias.rs` (section `divgrid`) is 4% faster, up to 0.65x, with nothing slower. **Static entries keep the cutoff rule** (approximate): `div.knuth` is their mandatory Knuth width, and when the rule selects BZ, or the shape cannot enter NR, they call Knuth at widths up to `div.bz` and BZ above it; each reads its knobs once into a `DivCutoffs` (`DivCutoffs::static_div()`, `static_div_rem()`, which also carry `knuth` and `bz_leaf`), so `div_alg_dispatch` is a pure predicate (invariant 6). Reciprocal selection depends only on `R = rcp.len()` and switches directly from Knuth to NR after `div.dyn_rcp_knuth_nr` or `div.static_rcp_knuth_nr`; the dynamic one and `div.bz` are sweeps (`tuner/sections/div.rs`: 22 and 99 on the M1; the leaf's sweep times both entries at 2d / d. Static entries cross to BZ later and share the knob: `div_rem_static<2048>` at 200/100 is 10% slower at 99 than at the default 140). `div.bz` is at least 3, as BZ's 2/1 step halves the divisor and Knuth needs two limbs. Number-type callers allocate the quotient or reciprocal buffer and call one of these entries directly; there are no allocating `div_vec`/`div_arr` adapters.

  The low-level building blocks remain `div_prim`/`div_buf_of` for normalized Knuth division, `div_2_1`/`div_3_2` for Burnikel-Ziegler recursion (`div_3_2` multiplies its quotient piece by the divisor's low half at the piece's significant width, and not at all when it is zero), and the shared `nr_err_band`/`nr_refine_rcp`/`nr_rcp_chain`/`nr_refine_quo` correction pipeline for Newton-Raphson. Four prepared division drivers apply operand windows, attempt NR, and explicitly retry through BZ on failure before preparing classical storage. NR attempts report success or failure and preserve the numerator on failure; remainder correction commits only after success. Two reciprocal drivers similarly own the NR/Knuth choice and retry. Dynamic drivers provide `ScratchGuard` buffers; static drivers provide `[u64; N]` buffers. Only shared arithmetic kernels accept multiplication callbacks.

  `RcpCarry` lets successive dynamic divisions by growing prefixes of one divisor share a reciprocal. `div_carry_dyn` and `div_rem_carry_dyn` are `div_dyn` and `div_rem_dyn`, with the same dispatch, plus a carry that `nr_quo_est_dyn` reads and leaves; BZ and Knuth leave it alone, since a reciprocal of a shorter prefix stays valid. `nr_rcp_resume` restarts the chain (`nr_rcp_steps`, `nr_rcp_chain`'s refine loop) from the widest step the carried precision reaches, truncating the seed to that step's p + 1 limbs, so usually only the last refinement runs. Its first band must be p + 1 limbs, which a seed with a limb to spare always is. Any other seed is rejected, x is cleared and the chain starts from its one-limb seed, so a bad seed costs a restart, not a wrong result. A zero seed is the one its own band can't see, since d·0 has no error limbs: the quotient's band fails it and the driver retries through BZ. `keep` stores the normalized reciprocal only when the quotient didn't fail, and skips one wider than the buffer. Static division has no carry.
- **`series.rs`** (formerly `bin_split.rs`) — Series evaluation. Binary splitting for BBP, Engel and Hyper series, each with a dynamic (exact `Vec`) and a static (`[u64; N]`, low bits dropped) node. Each kind also has a wide trait (`WideBBPSeries`, `WideEngelSeries`, `WideHyperSeries`) whose `p`/`q`/`r` return u128 and, like `neg`, take a u128 index: every narrow series is a wide one through a blanket impl (which narrows the index back, as the tree's indices are u64), and the nodes are bounded on the wide traits. A leaf whose values all fit u64 runs the narrow kernel unchanged through the `Narrow<S>` view (for a narrow series that check is a constant), and any other leaf a wide kernel that takes one term per step, with `mul_prim2` and two-limb carries (`push_or_drop2`, `add_term_wide`). A type implements one of the two traits, and calling `p`/`q` on a concrete narrow series with both in scope needs `<T as BBPSeries>::q`. `bin_split`/`bin_split_tree` take no cutoff: a tree splits `[a, b)` while it has more than `Node::leaf_terms()` terms and `Node::limbs` (an O(1) estimate of the node's largest part, capped at N for static nodes) is at least `Node::leaf_limbs()`; those trait methods return the node kind's knobs (section `bin_split`: `<dyn|static>_<bbp|engel|hyper>_leaf_limbs`, `<dyn|static>_hyper_leaf_terms`), and `SplitCutoffs::of` (no longer a `const fn`) reads them once per tree. The parallel split compares the same estimate with `bin_split.dyn_par`, and only on a pool of two or more threads; a split started off the pool (on the caller's own thread, where it has to wake the pool: a 2-term tree at 1024 limbs took 15.8 µs split against 2.1 µs serial) also needs `bin_split.dyn_par_work` of limbs times terms at the node (`SplitCutoffs::splits`; on a pool worker the limb gate alone decides, as it was tuned through exp and ln, whose chunks build their trees on workers), and binary splitting's runtime equation charges such a tree one wake (`Parts::wake`, priced by `bin_split.dyn_wake_ns`, which the tuner measures as a 2-term tree's time split less serial); a merge's two products run in parallel from `bin_split.dyn_merge_par` limbs. Limbs replace the old per-caller term counts because bits per term vary by orders of magnitude between series. Hyper also keeps a term floor, because a wide x makes each leaf step a full multiplication. `bin_split_tree_at` takes explicit `SplitCutoffs` for tests and `benches/bin_split_cutoffs.rs` (deleted 2026-11-09; at commit `faa9971`). See `docs/bin_split_cutoff_tuning.md`. `Node::finalize(ctx, zeros, out)` writes S·2^(64(out.len() + zeros)), skipping `zeros` leading limbs the caller knows are zero, so a small value deep below 1 costs only its significant limbs. Dynamic nodes finalize with `ratio_to_fraction_dyn` (one `div_dyn` sized by the output), static ones with `ratio_to_fraction_static` (a reciprocal and a high product, since that division's numerator wouldn't fit N). Static finalize takes a (len + 2)-limb reciprocal, whose error below one of its limbs costs out under 1 ulp, and requires `out.len() + 2 <= N`; at `N − 2` that reciprocal is N limbs, which `rcp_static` handles through NR. Its high product's overflow limb has no slot once y has len + 2 limbs, where S < 1 makes it zero. Static parts (P, Q, R) are `m · 2^e` with `m` in N limbs and `e` a bit exponent: exact while they fit, and afterwards their top 64N bits (P within two bits of that, and leaf parts keep one spare bit once they drop, so a term can go in over several passes). BBP keeps separate P and Q exponents like Engel and Hyper, so Q no longer carries 2^(shift·t). A merge computes P's exponent from its operands' bit lengths before any product (`p_exponent`), and each product only down to it (`product_at`/`hi_mul_from`); Q and R are normalized to their top bit (`hi_mul_norm`). A node loses at most about 11 bits below 64N (`test_static_nodes_keep_bits`), so static and dynamic finalize agree within 1 ulp all the way to finalize's `N − 2` bound; with limb exponents a node lost up to 3 limbs and was off by up to 2^63 ulps there. The last x-leaf of a sum keeps its running term t only from P's exponent up, since it never becomes R. Each static node's `ratio(ctx)` gives (P, Q, shift) with S = P / (Q·2^shift), which `finalize` and `ln2_static` divide. See the static section of `docs/bin_split_cutoff_tuning.md` for the cost. The Hyper x-leaf multiplies by x before each term, so a Hyper node sums x^(n−a+1) as `HyperSeries`'s formula states, and its R product for merges is unchanged.
  `series_eval_dyn(ctx, out) -> (bool, usize)` and `series_eval_static::<N, C>(ctx, out) -> Result<(bool, usize), CapacityError>` are the public entries. `ctx` is a typed context, `Bbp::<S>::new(shift)`, `Engel::<S>::new(shift)` or `Hyper::<S>::new(x, shift)?`, and its constructor's bound (`S: WideHyperSeries`, …) makes a context of the wrong kind for its series a compile error (a `compile_fail` doctest on `Hyper::new` checks it). A series with two kinds, like `Exp` (Engel and Hyper) or `ATanh` (BBP and Hyper), is picked by the context. `Hyper::new` returns `HyperCtxError` unless x is trimmed and nonzero with x·2^-shift ≤ 1/2. The sealed `Series` trait maps each context to its dynamic and static nodes (`type Static<const N: usize>`), derives the decay s with |x·2^-shift| ≤ 2^-s (the shift for BBP and Engel, shift − ⌈log2 x⌉ for Hyper), and gives `zeros()` and `range(bits)`. Each kind trait requires `const START`, the first term's index (term n is weighted 2^(−k(n − START + 1)), with x^(n − START + 1) for Hyper), and `tail_bits(n, s)`, a lower bound on −log2|R_n| for the tail R_n from term n (0 is always valid; `no_tail!` in the tests and benches gives it to series only summed over explicit ranges). `Exp` and `ATanh` share one bound per kind pair (`exp_tail_bits`, `atanh_tail_bits`), and the Engel/Hyper and BBP/Hyper impls call it. `zeros()` is `tail_bits(START) / 64`, since R_START = S, and `range(bits)` finds the fewest terms whose bound reaches `bits` by doubling, then bisection (`min_end`), panicking past 2^40 terms. Any valid bound is correct; a monotone one gives the fewest terms. The entries sum to 64·(out.len() + zeros) bits, out's own last limb (callers keep their own guard limbs), write out = S·2^(64(out.len() + zeros)) within 2 units of S, and return (S < 0, zeros). Fixed-frame callers size out with `zeros()` first. The static entry returns `CapacityError` before touching out unless out.len() + 2 ≤ N (static finalize's bound; Horner's and rect's +3/+4 stay eligibility checks) and a Hyper x fits N. The doc-hidden `series_eval_dyn_at`/`series_eval_static_at` force an algorithm. Underneath, the doc-hidden node-level `series_eval_range::<N>(ctx, a, b, zeros, out) -> bool` sums an explicit range over the node types (`DynNodeEngel<Exp>`, `StaticNodeHyper<N, ATanh>`, …), for tests (and formerly `benches/series_cutoffs.rs`), which need explicit ranges, zeros and contexts the typed constructors reject. It writes S as `Node::finalize` does and returns S's sign, choosing among reverse Horner, rectangular splitting and binary splitting (`SeriesAlg`). Binary splitting is `bin_split::<N>(..).finalize(..)`, unchanged, and `bin_split`'s API is untouched. The `SeriesNode: Node` trait, implemented for all six nodes, gives `eligible` (one O(t) pass returning an `Eligible { horner, rect }`, whose `allows(alg)` is always true for bin_split), `costs`, `dispatch`, `horner` and `rect`, plus `const RECT`: true only for the Hyper nodes, and `series_eval_at` asserts it before calling `rect`, whose default body is unreachable. The trait's items and `Eligible` are `#[doc(hidden)]`, since only the `series_eval_*` functions and the tests use them. `series_eval_at` forces an algorithm for tests and future tuning, and `rect_dyn_m` and `rect_static_m` (public, doc-hidden) force rect's block length through the same implementations as the default policy. trans.rs's exp and ln series go through the typed entries. The constant caches still call bin_split, since π needs its node's P and Q and ln 2 folds each share's weight into Q, and take only their term counts from `range`. Horner and rect share the factored-shift frame F = S·2^(64w), w = len + zeros + 1 guard limb. The per-term 2^-k is never applied: term n's p(n) lands at bit 64w − k(n − a + 1), an O(1) add at an offset, so the accumulator (len + 3 limbs for narrow coefficients, len + 4 for wide) is F from the first step and deep terms only touch the limbs they reach. There is no final shift. The steps run from n = b − 1 down, and consecutive terms whose ∏q fits the group budget share one division (`group`; `div_prim` up to 64 bits, `div_prim2` up to 128): BBP `acc += p·2^d / q` (each quotient through a temp), Engel `acc = (acc + p·2^d)/q`, Hyper x = 1 `acc = (r·acc + p·2^d)/q`, and Hyper x ≠ 1 `acc = x'(r·acc + p·2^d)/q` with x' = x·2^-bits(x) ∈ [1/2, 1). The last one normalizes x once (`normalize`), takes its products as `hi_mul` windows one limb lower (`mul_frac`), and uses k − bits(x) as the frame's shift. A group of m terms is one multiplication by R = ∏r and one division by Q = ∏q, with term k weighted by ∏_{i<k} q_i·∏_{i>k} r_i (`fold_group`; Engel is Hyper with r = 1 through `EngelHyper`). For x ≠ 1 each step keeps its r and x' products and only the division is deferred, and BBP sums the group's numerator Σ p_k·(Q/q_k)·2^d_k in its temp. The budget is 64 bits per accumulator limb past the single-term layout, capped at 128 (`group_budget`): the un-divided value is Q times what one step divided by q, so the old per-term headroom bounds Q instead of q. A group always takes one term and at most `GROUP_MAX` = 32, and stops early if p·Q would pass u128. Dynamic Horner always allocates the wide accumulator to get the 128-bit budget; static Horner does so when N has room (`horner_room`), so its capacity bounds don't change. Grouping made Horner about 3× faster at 16 limbs and 6–12× from 64 to 1024 for x = 1 and BBP. Rect (Hyper with x of two or more limbs only) precomputes x'^1..x'^m at len + 3 limbs and records each power's zero low limbs (`low_zeros`), which its products and term adds skip, so a block costs P × (its power's significant limbs) rather than P × P (3–12× faster from 64 limbs). Per block of m terms it takes one high product by x'^s, then Horner's scalar steps adding p(n)·x'^(i+1) instead of multiplying by x'. Static rect keeps at most `RECT_MAX_M` = 16 powers on its stack. Horner accepts u128 coefficients and selects a narrow or wide kernel once per range; wide numerators are added as two limbs at their signed frame offset and Hyper uses `mul_prim2` with both carry limbs. Rect still requires narrow coefficients. Both need Hyper's r(n) ≤ q(n) and k ≥ bits(x) (so no step scales the error below it up). Static nodes need out.len() + 3 ≤ N for narrow kernels and out.len() + 4 ≤ N for wide Horner; dynamic wide accumulators reserve that extra limb too. They agree with the exact sum within one unit of out's last limb, not bit for bit with bin_split. For a static node (`SeriesNode::TABLED` false; a dynamic node has its measured table in this place since 2026-11-12, and no `horner_first`), `dispatch` (and `series_eval_range`) first takes Horner without the model when `horner_first` says so: at most `series.horner_limbs` (28) output limbs and Horner eligible, for a Hyper range whose x is one limb (where the model picks Horner anyway) or a BBP or Engel range of at most `series.horner_terms` (12) terms (where Horner beats the model plus its pick, as the model there wrongly favors bin_split); at 1–4 limbs the model costs about as much as the sum. **Ahead of all of it a dynamic node reads the small-series table** (`SeriesNode::small`, since 2026-11-11, the user's decision: "for small series use a table as is done for other algorithms"): `series.small`, a measured table knob like `mul.kara`, whose row is `kind × 16 + the frame's bucket` (`small_frame`: the octave of the frame's limbs, 16 buckets to 65535; `SMALL_ROWS`) and whose change points run over the terms; a cell is Horner, rect, binary splitting or "the equations" (`SMALL_PICKS`). A kind (`small_class`, `SMALL_KINDS`, 8) is the family and x's width: BBP, Engel, and Hyper with no x, an x to a limb, of 2 limbs, 3–16, 17–32, more; the lookup costs a coefficient or two (only to leave out coefficients past 64 bits, which the table doesn't hold), with no `Shape` built. The layout is the table's size, and changing it means raising the series section's `derive` number in `tuning/schema.rs` (5 now), so that a file's table of the old layout falls through to the default instead of being misread, and measuring the table again (`cargo tune tune series --tables`). The table's pick is checked against the range's own eligibility and falls to the equations otherwise, so any valid table is correct; rect's block length is still the model's. **The tuner measures the table** (since 2026-11-12, the user's decision; `sections::series::small_table` through `tuner/tables.rs`, and the rules on tables under "Tuning rules"): for every kind and every octave of frames, at the octave's smallest frame, over the terms by thirds of an octave (each step at its last count), the kind's **members** are timed (`member_cell`, 72 synthetic series: `Big<LQ>` for BBP, `Den<LQ>` for Engel and for Hyper with r = 1, `Geo<LQ>` with r past 1, LQ of 8, 16, 32 and 62 bits, at x of 12 and 60 bits, 2 limbs, 7 and 14, 28, and 48), each summed by every algorithm that can, forced over the explicit range (`series_eval_at`), with the decision timed beside them (`decide_probe`: the shape, the guards and the equations at explicit knobs, `Shape::decide_with`). A cell is the pick that costs its members least together, the mean of each one's time over its own fastest algorithm's, and **reading the equations is one of the picks**, at the decision's cost: where no one algorithm serves the kind's spread (Horner 2× off for a small q, binary splitting 2× off for a large one) the cell is the equations' and the row goes on. A row ends where the decision is within the share of the shortest series of every member, and a kind is closed at the first octave whose row ends at its first index. (Until 2026-11-12 the table was derived from equations fitted to short series, at a representative `Shape` and out to a predicted 20 µs, and a near tie between two equations that were a factor of three off put binary splitting where rect was 30× faster; and until later that day its rows were 72 classes, a kind of ten by q's bits in four buckets and by an r past 1, each timed on one series: about 1870 change points, cut to 218 by the user's choice of layout.) The default table hands everything to the equations. Past the table `dispatch` runs `decide`: one **guard** on a ratio of the shape first (dynamic nodes, since 2026-11-11; `Shape::guards` at explicit `SeriesGuards`, `Shape::decide_at`), then the least prediction: `costs` (doc-hidden, like `eligible`) returns a `Costs` of every eligible algorithm's predicted ns, which the tests and the tuner read, and `pick` chooses. The shape's two ratios are **rho** (`Shape::rho`: x's bits over the bits a term fixes, the frame's bits over the terms) and **beta** (`Shape::beta`: the exact fraction's width, the tree's P, over the frame). Rect is taken outright, at the balance block length (`rect_cands`' first, unpredicted), where rho reaches `series.rect_rho` (32 on the M1) and x has at least `series.rect_x_limbs` (16) limbs. **There is no guard on beta since 2026-11-13** (the user: "if the beta gaurd is causing a slow down remove it and rely purely on the table and the fired equations"): binary splitting used to be neither predicted nor taken past `series.bin_split_beta` (8) frames of tree where another algorithm could sum the range, and once its equation fitted the guard was barring it where the equation was right (67% and 75% slow on two unseen series of a few microseconds); its equation is read at any beta now, which costs the decision the tree's walk (0.2-0.6 us on such ranges), the table's to answer for on a short series. Static nodes have no guard. **Dynamic nodes compare fitted runtime equations, one an algorithm** (`SeriesEq`, since 2026-11-10, the user's decision; `Shape::horner_parts`, `rect_parts`, `bin_split_parts`). Each equation is the algorithm's own `Parts`, read off its kernel, times fitted prices: multi-limb products in ns by mul's equations (`MulEq::mul_ns`; a high product by `SeriesEnv::hi`, which follows `hi_mul_dyn`: a `mul_prim` pass for a one-limb operand, `hi_mul_buf`'s own equation (`HiEq`, since 2026-11-12) up to `mul.dyn_partial_mul` limbs, the guarded product above, whose window is copied out of scratch), finalize's division in ns by division's (`dyn_div_best`, Knuth's alone within its guard), and limbs of each kind of linear pass (`div_prim`, `div_prim2`, a one-limb multiplier, a two-limb one, additions and shifts, fills and copies), terms, kernel calls and allocations. A full product with a one- or two-limb side is a `mul_prim` or `mul_prim2` pass, not mul's schoolbook equation, which was fitted from 10 limbs up. Binary splitting's parts walk the tree `bin_split_tree_at` builds, level by level (a node of n terms is a leaf at `leaf_terms` terms or under `leaf_limbs` estimated limbs, else splits into n / 2 and n − n / 2, so a level holds two sizes at most): each merge's products by `Family::products` at its children's part sizes, each leaf's passes over parts that grow to their length (a step packs the terms whose coefficients fit a limb; an x-leaf multiplies its running term by x each term, and each of its terms is a `step`, with a price of its own), and finalize: its division by division's equations, or a pass a quotient limb at a price of the series' own by a Q of one limb (`div1`) or two (`div2`, since 2026-11-13: division's equations are fitted from four limbs, and Knuth's reads 27% high at two, 8.1 ns a quotient limb measured for 10.2). A tree wide enough to split across the pool has each level's work divided by 1 + gain·(threads − 1) (`series.bin_split_par_gain`, 0.3 on the M1's 8-thread pool: far from a full speedup) and pays one wake off the pool. Horner's parts: per group a division by Q over the frame at the group's shallowest term (`Shape::groups`, since 2026-11-13: for a q of one size the groups are whole, taken from the deep end, and the shallowest holds what is left; for a q that grows they grow towards the shallow end, where the frames are widest: the range's bits of ∏q (`Shape::qs`: q as c n^d through its two Gauss points, summed by Stirling's formula, as their mean alone is 2-3.5% high for q(n) = n) over what a group holds of its 128 give their number, the frames at the two Gauss points their divisions' limbs, and the shallowest group is a whole division at the first term's frame however few its terms; `div_prim2` once a group's Q passes 64 bits, so `div_prim` for a shallowest group whose few terms fit a limb; a first term left alone with q = 1, as exp's is, divides by nothing, as `div_prim` returns at once), by family BBP's numerator or Hyper's product by R, which runs over the sum as the group below left it (nothing for the deepest group, and a one-limb pass for a shallowest group of few terms), and with x per term a high product by x', summed over the range in closed form where every frame is `hi_mul_buf`'s (`Shape::school_products`: `HiEq` is a polynomial in the frame, so the frames run through the whole accumulator, then a falling stretch cut where the frame passes the kernels' cutoff `mul.hi_mul_row` and where it passes x, then one limb). Rect's (`Shape::rect_parts`, each count read against counters in the kernel on 2026-11-12): its m − 1 powers, each a high product of the whole accumulator by x', a copy either way and a scan for zero low limbs; per block but the deepest a high product of the sum so far by the block's power at that power's significant limbs, which are ceil(j·bits(x)/64) for power j (`power_step`, `power_limbs`: the powers are exact and the kernel skips their zero low limbs, so an x of two limbs steps by anything from 65/64 to 2); per group a division and a product by R at the frame of the group's own shallowest term (two lattice sums, `frame_from_lifted` at the groups' mean offset in a block; the narrow accumulator's budget makes Q one limb); and per term its weight times its power added over the lesser of the power's limbs and the limbs under the term's bit, in closed form a block (the powers grow as the frames shrink, so the two cross; blocks that hold every power whole are taken in one step and the rest sampled), once plus `spill` of a second time (`add_term` skips the half of a weight that is zero: about 1 + bits/64 passes, not 2). The accumulator's own length is a fraction of a limb off a term's frame (`active_lifted`: the sum a division takes is Q/q times a term, and what it leaves is a q below it). Until then the model took a power as j·xl limbs, two passes a term over min(mean power, mean frame), and every group at its block's top frame: 1.74× the kernel's add limbs with a 22% spread, 1.15× its division limbs (1.42× at two blocks). Rect runs Horner's kernels, so it takes Horner's prices for the passes they share (the products by R, the copies) and fits its own for its products, its one-limb divisions, its term adds (`add_mul` passes, the `add` column), a term, and its fixed cost (`SeriesEq::RECT`; it has no price a call); Horner and binary splitting each have their own fit (one set of prices shared by the three, as the old model had, reads 17% and loses 2–2.6%). The knobs are `series.horner_ns_*` (8: product, div1, div2, mul1, light, term, call, step), `series.rect_ns_*` (5: product, div1, add, term, one), `series.bin_split_ns_*` (12: product, division, div1, div2, mul1, mul2, add, light, term, call, alloc, step), `series.bin_split_par_gain`, rect's two guard knobs and the table `series.small`; `Parts` has thirteen columns (`Parts::N`), the last `step`: Horner's groups, and an x-leaf's terms for binary splitting. **Horner's fixed costs are three since 2026-11-13** (the forms' rule under "Tuning rules"): a term (its coefficients, its weight and its add), a group (`step`: its division's reciprocal and the scan that forms it) and the calls a term's own step makes besides (`call`: three for a step by a one-limb x, as `mul_dyn` copies the operand and makes the pass and `mul_frac` copies it back; one by a wider x; one for BBP), where a price a kernel call, every call alike, read 5.8% held out on the kernel's own counts; and a pass by a two-limb multiplier is priced at `series.horner_pass2` times `mul1`: the ratio of `mul_prim2`'s ns a limb to `mul_prim`'s, a knob the series section's tune measures on the two kernels themselves (`sections::series::pass2_ratio`: each timed in place over 64-1024 limbs and fitted as a L + c; 3.46 on the M1), as a price fitted for such passes rests on the few series that make long ones; their defaults are the M1's fit (the table's: everything to the equations). **There is one set of prices** (`SeriesEq::read`), fitted on the series the equations are read for: those the measured table names no algorithm for (`Rows::Table`, in the section's second phase, `tune_late`, once the table is measured; the family is walked three times over for it). The table has to be measured under some equations (rect's block length under a table pick is the model's, and the decision is timed), so a tune fits twice from one set of timings: first on the series whose own timed decision is within the rule's share of the fastest algorithm's time (`Rows::Share`, `SeriesTiming::read`: what the rule says of one series alone), then, after the table, on what the table leaves. The two differ because the table's rows stand for kinds: a row goes on while any member of its kind is past the share, taking series that are within it, and a cell that hands its index to the equations leaves them series past it. (For part of 2026-11-12 there was a second set, `series.short_*`, fitted on shorter series and read only to derive the table; it went, with `SeriesEq::read_short`, `Shape::of_class` and the tuner's `Regime`, when the table became measured.) Rect has a price of its own for one-limb divisions, `series.rect_ns_div1` (approved by the user on 2026-11-12, "That addition to the Rect equation is ok"): its groups end at its blocks, so it makes one-limb divisions in every range, which Horner's long series hardly make (Horner's long fit leaves that price out at 0). `SeriesEq::RECT` is product, div1, add, term, fixed since later that day (it was product, div1, call, fixed), and the series section is at version 8 since 2026-11-13. There is one model of a group's size (since later on 2026-11-13): `Shape::group_room` (Q within the accumulator's budget and p Q within 128 bits), `whole_group` (the whole number of terms for a q of one size: the same number fits at both of the range's Gauss points, `Shape::gq`) and `group_count` (for a q that grows, the range's bits `qs` over what a group holds). Horner's `groups` builds its divisions on them, and `group_of`, rect's one size for all its blocks (its groups end at its blocks), is the whole number or the terms over the count. **Since 2026-11-11 (series version 4) the equations are fitted, and the guards swept, on a synthetic family and on no caller's series** (the user's direction; "Tuning rules" has the numbers): the figures in the rest of this paragraph are from the fit on exp's and ln's chunks that it replaced. On exp's and ln's own series (`cargo tune series`) the fits read 5.6% (Horner), 13.3% (rect) and 6.9% (binary splitting) rms and the picks lose 0.13% of measured time on the fitted workloads and 0.35% held out (worst 6.4% and 20%), where the shared prices over counted work lost 3.8% and 4.3% (worst 65%) with model errors of 17%, 59% and 31–102%; binary splitting's multiples on mul's and division's equations come out at 1.00 and 1.01. The fits are above the 5% line, so the tuner marks them NOISY (this was the model's one revision). The evaluation costs 40–60 ns for a BBP or Engel range and 55–230 for a Hyper one up to 64 limbs (the old counts: about 25), kept down by not predicting what can't matter and by closed forms: rect's block lengths only where Horner's products by x cost more than rect's fixed cost (elsewhere rect reads as Horner plus that cost, at block length 1), the pool only for a tree wide enough to split, a one-leaf tree without the level walk, a parabola in place of `log2`, and the schoolbook tier's sums in closed form (eight sampled evaluations of Horner's products alone took 3–5% off `exp_dyn` at 4–120 limbs; `sum_sampled` is left for the guarded tier, rect's blocks and a leaf's products past schoolbook, where the work dwarfs it). In a normal build against the tree before it: series workloads 0.977, exp and ln 0.984 (`benches/tuning_bias.rs`), outputs identical. **Static nodes keep the old model** (approximate, like every static decision): `Work`, each algorithm's primitive counts (division limbs, scalar-pass limbs times the scalar's limbs squared, as `mul_prim2` costs about four `mul_prim` passes, product work, terms, kernel calls and N-array limbs), times the six `series.ns_*` prices shared by the three (`SeriesModel`; fitted with `benches/series_cutoffs.rs` and `scripts/python/tune_series_cutoffs.py`, deleted when the constants became knobs and still at commit `faa9971`; see `docs/series_cutoff_tuning.md`), with product work as `mul::mul_work`, schoolbook limb products along `mul_static`'s tiers, each tier scaled at the crossover that selects it so it never jumps there. Rect's block length comes from the model in force (`Shape::rect_len` for dynamic nodes, `rect_best` for static: whichever of the a/m + b·m balance of block products against powers and term adds, 1, and the length whose power fills the accumulator it predicts fastest), so no constant sets it; the first candidate stands when no prediction is a number (a price at its maximum), which the random-knob test once found returning block length 0. `series_eval_range` evaluates the costs once and runs the pick at that block length without re-checking eligibility; `series_eval_at` still checks, and `rect`'s `m: Option<usize>` falls back to the model's length.
- **`trans.rs`** — Its knobs are sections `exp`, `ln`, `agm` and `theta` of the tuning schema (read as `k::exp::…()` and so on). ln's theta term count is a const generic, so `ln_dyn` and `ln_static` call `ln_agm_*_at::<T>` through `knob_generic!`: a const argument in a normal build, and in a tune build a `match` over the knob's valid values (0..=16 dynamic, 0..=9 static, the T whose plan fits `THETA_STATIC_SLOTS`), each arm binding `const T`. `exp_dyn(x, m: i64, out)` is the public e^X, with X = 2^(64m)·x, where x is a fixed-point number whose **top** limb is its integer part: the top limb is worth 2^(64m), so m = 0 is X in [0, 2^64) and m = −1 a full-precision X in [0, 1) (m = −(x.len()) puts X below an output of x's length, and e^X is then exactly 1: the tuner's exp workloads passed that until 2026-11-11, see "Tuning rules"). Top zero limbs fold into m, computed in i128, and x = 0 gives 1. It writes o = e^X / 2^(64k) ∈ [1, 2^64), with `out`'s top limb as o's integer part, and returns k. It returns `Err(ExpError::Overflow)` once k = n / 64 would pass i64::MAX (n ≥ 2^69, X ≳ 22.18·2^64), and returns it early when X ≥ 23·2^64. `exp_static::<N>` is its stack-only twin and needs `N >= out.len() + 3` (`out.len() + 4` once ln(2)'s out.len() + 2 limbs pass `ln2.bin`'s 1024, because it then sums them, without `ln2_static`'s own guard limb, through `ln2_static_unguarded`). A smaller N is a limit of the stack buffers, not an arithmetic failure, so it returns `Err(ExpError::Capacity(CapacityError { min_n }))` (checked before any input, leaving `out` untouched) instead of panicking; `CapacityError` lives in `utils/mod.rs`, and `exp_static_entry` and `ln2_static` return it too. `exp_static` takes the squares below only when N leaves room for the core at their frame's fs limbs (N ≥ fs + 3, so from out.len() + 4 while j ≤ 60), as they are only an optimization. `exp_dyn_at`/`exp_static_at` take the square count explicitly for tests and `cargo bench-bin-split exp` (deleted 2026-11-09; it runs at commit `faa9971`). Both are thin wrappers over `exp_reduced`, which takes the ln(2), division-with-remainder, core and high-square functions as `fn` pointers, like `exp_combine`'s `hi_mul`, plus three caller-provided buffers: pooled scratch for the dynamic path, `[u64; N]` arrays for the static one. Argument reduction is one exact division with remainder (`div_rem_dyn`/`div_rem_static`) of floor(X·2^(64F))·2^g by floor(ln 2·2^(64F + g)) (out.len() + 2 limbs of ln(2) shifted right by 64 − g), with F = out.len() + 1 and g = `EXP_RED_GUARD_BITS` (58). The quotient is n, at most 3 limbs, so the division is linear in F; the remainder, shifted back down by g, is r ∈ [0, ln 2) at F limbs, and out = e^r << (n mod 64). Only r's absolute error matters, and it is up to n times ln(2)'s truncation error, so ln(2) needs about 7 bits past F limbs for n < 2^69: one whole guard limb is not enough (with n mod 64 near 63 it costs ~16 ulps), and g = 58 leaves a wide margin. X's own truncation at F limbs is not multiplied by n. Guard bits instead of a second guard limb keep the numerator in out.len() + 3 limbs, since X < 23·2^64 has at most 69 integer bits. Before the core, r is scaled to r·2^-j, exactly, by a shift into xr's spare limb. j is `exp.dyn_sqr_bits`/`exp.static_sqr_bits` (24; 0 disables it) less r's own leading zero bits (`exp_sqr`), and 0 when the core would sum r's chunks in parallel (the entries' own gate, `chunks_par`, applied to their frame from `exp_frame`): the squares run serially, while the series they shorten would overlap. End to end, the best j hardly moves with precision (about 24 from 1 to 16384 limbs on one thread), so it is a constant: a multiple of log2 of the precision fit worse. The core then gives u = e^(r·2^-j) − 1 in a fixed frame of fs = out.len() + ⌈(j + 4)/64⌉ fraction limbs, and `exp_reduced` squares it back j times as u ← 2u + u² = (1 + u)² − 1 through `hi_sqr_dyn`/`hi_sqr_static`, reusing ln(2)'s buffer for the product. It never forms 1 + u, so the frame keeps u's low bits. Each square at most doubles the error below it and adds about a unit, and ∏(1 + uᵢ) < 2, so the j + 4 extra bits keep the total under a quarter of a unit of the out.len()-limb result. u < 1/2 before the last square, and on the last one only rounding can carry past 1, which saturates as in `exp_combine`. The core runs at fs − z limbs with the squares, and at out.len() − z limbs without them (j = 0), where z is its predicted leading zero limbs. The shift by n mod 64 < 64 moves only part of its last limb into `out`, and the core's own guard limb keeps that limb within about 1 unit, so it needs no extra limb. When X is within the error of a multiple of 64·ln 2, either neighboring k is valid, as (k, 1.000…) or (k − 1, 0xFFFF…). `exp_dyn_entry(x, m: u64, out)` is the reduced core. It takes bit-burst e^x − 1 for a fraction x·2^(−64(m + x.len())) < ln 2 and returns the zero limbs above `out`. It processes x's top bit, then chunks of its remaining bits, combined as (1 + a)(1 + b) − 1. Each chunk spans [s, ~2s) of its own offset s, except that the first one is at least `exp.dyn_chunk_min_bits` wide (near x's top the factorial, not the offset, sets the term count, so narrow chunks cost as much as wide ones). `chunk_bits` extracts and normalizes every chunk's bits into one pre-sized scratch buffer up front. One generic routine, `exp_series::<V>`, sums every series into its slot below its leading zero limbs (the context's `zeros()`), through `series_eval_dyn` or `series_eval_static` as the private `Eval` trait picks: an `Engel::<Exp>` context when the bits are a single 1 (the top bit is that case, at its exact shift), otherwise `Hyper::<Exp>`. `Exp`'s tail bound sets the term count, and the cost model picks Horner (most chunks up to about 64 limbs), rect or bin_split per series. Each series is sized by its own leading zeros, so only the accumulator carries the slack limb for a top bit on a limb boundary. The top bit's series runs on its own, straight into the result. Every chunk then fills its own slot (Σ bl limbs from a single scratch acquisition, never per-thread buffers), serially or on rayon, and the slots combine in chunk order, so both paths give bit-identical output. The parallel decision is made once per call: `chunks >= 2 && chunks * v >= exp.dyn_chunk_par_work` on a pool of two or more threads, with `v` the result's working limbs. Precision alone predicts badly, because leading zero limbs (m > 0) shrink per-chunk work. Both are knobs of section `exp`. One `exp.dyn_chunk_min_bits` serves the serial and the parallel path, which want opposite values (64 at every size run serially, 8–32 once the chunks run on the pool: see "Tuning rules"). `exp_static_entry::<N>` is the stack-only twin and needs `out.len() + 3 <= N` (otherwise `Err(CapacityError)`); m and x.len() are unconstrained. That is the floor for an accurate result: each series needs one guard limb past out, static finalize needs 2 more, and the guard limb absorbs finalize's last-limb rounding. It uses the same frame and schedule (`exp.static_chunk_min_bits`), with `[u64; N]` buffers, `series_eval_static` through the same `exp_series`, and `hi_mul_static` in `exp_combine`, which takes the high-product function as a parameter. `exp_chunk_static` evaluates one chunk end to end. Once `chunks >= 2 && chunks * v >= exp.static_chunk_par_work` (at most 64 chunks, on a machine with two or more CPUs), each chunk gets its own scoped thread with a `static_split_stack(N)` stack (through `static_jobs`, shared with the static constant caches) while the caller's thread sums the top bit's series. Results join and combine in chunk order, so the serial and threaded paths agree bit for bit. Only the threaded path touches the heap, through std's thread and join packets, as `ln2_static` does. `exp_static_entry` matches `exp_dyn_entry` exactly on almost every input; the rest differ by 1 in the last limb, and both stay within 1 ulp of the truth. `Exp` is `pub` so `benches/bin_split_cutoffs.rs` (deleted 2026-11-09; at commit `faa9971`) sums the same series. See the exp section of `docs/bin_split_cutoff_tuning.md`.

  `ln_dyn(x, m: i64, out)` is the public ln X, taking X as `exp_dyn` does. It writes o with |ln X| = o·2^(64k), o ∈ [1, 2^64) and `out`'s top limb its integer part, and returns (k, negative). X = 1 zeroes `out` and returns (0, false), and X = 0 returns `Err(LnError::Zero)`. `ln_reduced` (shared through `fn` pointers like `exp_reduced`) normalizes X to u = X·2^-e ∈ [1, 2), except that X ∈ [1/2, 1) stays u = X with e = 0, since −ln 2 + ln 2X would cancel |ln X|'s leading bits without bound for X just below 1. δ = |u − 1| comes straight from x's limbs (`Delta`, with 1 − u = !f + 1 exact through f's lowest nonzero limb). It takes j = floor(A·log2(64·out.len())) square roots (`ln.dyn_sqrt_a`/`ln.static_sqrt_a`), less the bits by which u already sits near 1, so an input near 1 skips them. Each is one `sqrt_approx_*` of a (fl + 2)-limb radicand 4y·B into an (fl + 1)-limb root, shifted right 33 bits (pi_root's half-limb trick), the same for every y ∈ [1/2, 2). Then it runs the core on δ_y = |y − 1| (o + 1 limbs when e = 0, so the 2^j shift keeps every bit) and recovers |ln X| = 2^j·L, or |e·ln 2 ± 2^j·L| (ln 2 at o + 2 limbs times |e| < 2^70, at o + 1 fraction limbs). `ln_dyn_entry(x, m: u64, neg, out)` is the reduced core: |ln(1 ± δ)| for δ = x·2^(−64(m + x.len())) < 1 (δ ≤ 1/2 when neg), returning the zero limbs above `out` as `exp_dyn_entry` does, with the same extra-limb frame (`ln_frame`). ln(1 ± δ) = 2 atanh(z) with z = δ/(2 ± δ). Chunks split z, not z², because atanh has an addition rule and ATanh(z²) doesn't: atanh(z) = atanh(a) + atanh((z − a)/(1 − za)). `ln_chain` keeps the residual as a fraction n/d updated by n −= a·d, d −= a·n, two short×long `hi_mul` products, so neither z nor any residual is ever divided out. A chunk's bits come from one short division of n's and d's top limbs, sized by the chunk (`chunk_quotient`), with d rounded up so a ≤ z and n stays ≥ 0. The residual's top bit is found exactly, by comparing n's and d's mantissas. The first chunk is that top bit, summed through a `Bbp::<ATanh>` context at shift 2k. Every later chunk spans [s, ~2s) from the residual's actual top bit, exp's width rule (`chunk_width`, `ln.dyn_chunk_min_bits` once), as a Hyper `ATanh` over A² with shift 2k, or BBP again when A = 1. Each chunk adds 2a exactly and 2a·ATanh(a²), its series sized by its own leading zeros (`ln_chunk` gives the frame wi and a lower bound on those zeros; `ln_chunk_sum` sizes the slot by the context's `zeros()`, and `ATanh`'s tail bound x^n/((2n+1)(1−x)) at s = 2k − ⌈log2 A²⌉ ≥ 2·lead, sets the terms) and multiplied back by A (`mul_shr`). The chain stops once the residual's top bit passes ⌈64w/3⌉ + 2 (and the top chunk's), where its cubic term is below the frame, and the tail 2n/d is one `ratio_to_fraction_*`. So nothing is divided between chunks, and the results simply add. The dynamic core runs the chain serially (its products are cheap), then every series into one scratch acquisition, serially or on rayon (`ln.dyn_chunk_par_work`), alongside the tail through `join2`; the two paths agree bit for bit. `ln_static_entry::<N>` needs N ≥ out.len() + 3 (m and x.len() unconstrained). Its chunks come from the serial chain, so threads start as the chain finds them (`static_split_stack(N)` stacks, at most 64, decided from the predicted chunk count), while the caller sums the top chunk and the tail. `ln_static::<N>` needs N ≥ out.len() + 4, which covers ln 2's o + 2 limbs past its table. It takes the square roots only when N leaves them room, as they are only an optimization. With exp's squares, `ln_dyn` takes 1.2–2.2× `exp_dyn`'s time on one thread from 1 to 16384 limbs (about 0.96× at 256); on 12 threads 1.1–2.3×, except 0.7–1.0× at 96–512 limbs, where ln's chunks already run in parallel and exp's do from about 128 limbs, without squares. `ln_dyn_at`/`ln_static_at` take A explicitly for tests and `cargo bench-bin-split ln` (deleted 2026-11-09; it runs at commit `faa9971`); `ATanh` is `pub` like `Exp`. The chunk-width and parallel knobs are still `// GUESS`.

  `theta_dyn::<T>(x, shift, th2, th3) -> usize` and `theta_static::<N, T>` are the first step of an AGM–Jacobi logarithm, ln(1/q) = π/(4·AGM(θ2², θ3²)) (`docs/agm-ln-theta.md`). They compute θ2(q⁴) = 2Σ_{k≥0} q^((2k+1)²) and θ3(q⁴) = 1 + 2Σ_{k≥1} q^((2k)²) for q = x·2^-shift < 1/4 (x trimmed and nonzero, l = shift − bits(x) ≥ 2, asserted). θ3 keeps k = 1..T and θ2 keeps k = 0..T, the doc's N as a const generic (at most `THETA_MAX_TERMS` = 16), less any term below its output. th3 = θ3·2^(64(th3.len() − 1)), with its top limb the integer part 1. th2 = θ2·2^(64(th2.len() + z)), and the functions return z = ⌊(l − 2)/64⌋; θ2 ∈ [2^-l, 2^(2−l)), so th2's top limb has at most 64 leading zero bits. Each output is at most 1 unit of its last limb below the truncated sums, since every product only drops bits. The powers q^(n²) follow one of two compile-time plans (`theta_plan.rs`, `ThetaPlans::<T>::SERIAL`/`PARALLEL`) of squares and products, odd n to θ2 and even n to θ3. Each mantissa is kept normalized with a bit exponent beside it (`theta_norm`), and the powers of 2^-l only decide where a term lands (`ThetaSchedule::place`). Each accumulator keeps one guard limb: odd terms go to θ2·2^(64z), even ones to θ3 − 1. Term n's window is the frame limbs at and below its top, z_n = ⌊(l·n² − 1 − 64t)/64⌋ down, plus one guard limb (`ell`). One backward pass (`Theta::new`) gives each value the widest window among the terms it feeds, so every product takes its operands' top limbs at that width, and a value feeding only terms below the frame (width 0) never runs; this follows the wider output when th2.len() ≠ th3.len(). The gate picks the plan from the frame alone: `PARALLEL` from `theta.dyn_par_limbs` (256) or `theta.static_par_limbs` (1024) frame limbs (`// GUESS`), else `SERIAL`, and threads it when there are two or more workers. Threads never change the bits: each op is deterministic and the terms add exactly. `SERIAL` runs in plan order on its compile-time slots (dyn: exact widths carved from one scratch acquisition; static: `[[u64; N]; THETA_STATIC_SLOTS]`, 8). The threaded `PARALLEL` is a dataflow with one join (`Flow`): ops dispatch in plan order once their operands are done and a slot is free, from a pool of `slots + workers − 1` equal slots (`SlotPool`, a small `unsafe impl Sync` table whose safety rests on that scheduling), and each finished op adds its term, frees what it read last and dispatches more, all under one mutex. With nothing running, the values alive are the in-order ones, so a pool of the plan's live peak never deadlocks. Dyn runs it on `rayon::scope` (each finished op spawns its successors), static on `thread::scope` with `static_split_stack(N)` workers on a condvar, catching a panicking op so the others stop. Doc-hidden `theta_dyn_at::<T>`/`theta_static_at::<N, T>` take a `ThetaMode` (`Auto`, `Serial`, `Parallel { threads }`). The static entry needs N ≥ max(th2.len() + 2, th3.len() + 1), checked before any input (otherwise `Err(CapacityError)`, outputs untouched), and T's `SERIAL` plan to fit `THETA_STATIC_SLOTS` (a compile-time assert; to T = 9); it runs `PARALLEL` only if that fits too (to T = 6). Dyn and static agree within a unit, not bit for bit, because their high-product tiers differ.

  `agm_dyn(a, b, out)` and `agm_static::<N>` are the second step, the arithmetic-geometric mean. They run on integers at one scale: AGM(λa, λb) = λ·AGM(a, b), so a, b and out share the caller's fixed-point frame (a.len(), b.len() ≤ out.len(), shorter ones zero-extended). They write the limit AGM(a, b) within a few units and stop on their own: before each step, `agm_tail_ready` bounds the term count of the AGM's closed-form tail from the bit lengths of a, b and a − b (read from the top limb where they differ), and once it is at most `agm.dyn_tail_terms`/`agm.static_tail_terms` (10 and 4) `agm_tail` finishes. A zero input gives 0 at once, and a = b gives a. `agm_core` (shared through `fn` pointers) keeps the running a in `out`, with b and four scratch buffers at out.len() + 2 limbs (the product's top in one). Each step takes only the top h = min(t, ⌈t/2⌉ + 2) limbs of the trimmed pair's t-limb product through `hi_mul_*` (the whole product, exactly, while t ≤ 5), larger operand first so swapped inputs make the same products. The arithmetic mean is an add and a one-bit shift, with the carry put back at the top. The geometric mean is one `sqrt_approx_*` of that window back to ⌈t/2⌉ limbs, which reads it as padded by its t − h dropped limbs (the sqrt's x·B^(2·s.len() − x.len()) form): a radicand error below B^-(⌈t/2⌉ + 1) of the product, which moves the root by under 2^-33 units, though a perfect-square product can now come out a unit low. The root reads an odd t as padded by one more low zero limb, so its root comes out 2^32 too high and is shifted back down, exactly: ⌊⌊√(p·B)⌋/2^32⌋ = ⌊√p⌋. Each mean is within a unit of the exact mean of its computed pair. A unit in b_k < a_k costs up to about a_k/b_k units of the result, though, so the frame must give the smaller input (θ2², about 2·log2(1/q) bits below θ3²) its full precision. Its zero limbs cost little, since trimming skips them in the first products and roots. `agm_tail` sums AGM(m + D, m − D) = m·(1 − Σ g_i u^i), m = ⌊(a + b)/2⌋, D = ⌊|a − b|/2⌋, u = (D/m)² < 2^-2t, t = bits(m) − bits(D) − 1, where g_i = N_i/2^(e_i) (`AGM_TAIL`, 19 positive falling dyadics: 1/4, 5/64, 11/256, …) is the inverse of K's series, so the next term bounds the rest (`agm_tail_terms`). The correction is C = D·ε·H(u), ε = D/m, H = Σ g_i u^(i−1), so no product by m. Every value is a floor at one guard past what C needs, and the frames shrink by 2t bits a level: ε through one `ratio_to_fraction_*` at we = ⌈(2·bits(D) − bits(m) + 24)/64⌉ limbs, u = ε² by `sqr_shr` (a high square, `mul_shr`'s twin), Horner's h_i = g_i + u·h_(i+1) through `mul_shr` with u's limbs below each level dropped, ε·H = ε/4 + ε·(u·h_2), and C·2^64 = D·(ε·H) from D's top limbs. Only the division and the last product run at C's width. out is within 2 units of the limit of the pair the tail starts from (measured within 1). The gap doubles each step, so the series j steps before convergence needs about 2^(j−1)…2^j − 1 terms: `cargo bench-bin-split agm` (deleted 2026-11-09; it runs at commit `faa9971`) put dyn's best at j = 3 (6–7 terms) and static's at j = 2 (3 terms, as its ε is a reciprocal and a product) at every size, and `agm_dyn` takes 0.935–0.953 of the old means-only time from 64 to 16384 limbs (`docs/agm_profile.md`). The dynamic caches go parallel (rayon) when new·(cached² + HALF²) ≥ CUTOFF·HALF² in output limbs (`cache_par`, saturating so every knob value is valid, with the knobs `consts.dyn_ln2_par`/`_half` and `consts.dyn_pi_par`/`_half`): extending also merges into the cached nodes and finalizes at the full length, so a few new limbs on a large cache still pay. - **`sqrt.rs`** — Square roots: binomial (`binom_sqrt_core`) below each output mode's top-level cutoff, Zimmermann above, with exact root and remainder (`sqrt_dyn`/`sqrt_static`), exact root only (`sqrt_only_*`) and floor-or-one-above (`sqrt_approx_*`) outputs. `zimmerman_sqrt_entry` runs one stage, both the top one (each output mode, with padded inputs read as x·B^p) and, as `SqrtOutput::Stage`, every recursive one, which leaves x above the remainder unspecified; `zimmermann_sqrt_core` is the leaf check in front of it. Both are shared by the two allocation models through division and square callbacks, and `normalized` is every top level's normalization, one-limb roots included. The `zimmerman_sqrt_*` names are `pub use` aliases of the `sqrt_*` entries. A stage's remainder R = X − s² lies in [−(2s − 1), 2s], so dynamic stages of at least `sqrt.dyn_wrapped_rem` root limbs whose m = `bnm1_size(k + 1)` is at most `FFT_BNM1_16BIT_CUTOFF` form it from residues mod B^m − 1, rather than from the division's remainder and the low root's square. They fold X before the child overwrites its top half (`fold_mod_bnm1`, then a limb rotation by p for a padded top), divide quotient-only (⌊⌊N/s′⌋/2⌋ needs no odd fix-up), square s once with `sqr_mod_bnm1_dyn`, and read R's sign from the residue's top bit. That drops NR division's whole q·s′ remainder product. The roots and remainders are bit-identical to the classic stages'. Recursive stages take it in every output mode; at the top it applies only to the root-and-remainder output (the root-only top usually skips its square, and the approximate one has none). Static passes no cutoff (`None`) and keeps the classic stages. The doc-hidden `sqrt_dyn_at`, `sqrt_only_dyn_at` and `sqrt_approx_dyn_at` take the cutoff explicitly (`usize::MAX`: classic everywhere). Dynamic roots of at least `sqrt.dyn_rcp_carry` limbs also carry one reciprocal up the recursion (`RcpCarry`, `s.len()/8 + 8` limbs). The recursion is linear and each stage divides by the whole root of the stage below, so the carry lives in `sqrt_dyn_output`'s division closure and the core never sees it. A stage's NR division starts from what the last NR stage left, as the child's precision passes the parent's second-to-last chain step by 1–2 limbs (modeled at every width to 40000, for full and (k + 2)-limb inputs; a seed that falls short only resumes from further back). Every divisor's top bit is set, so normalization never shifts, and a stage's final −1 can borrow into limbs a lower stage divided by only by moving the divisor's value a unit, far below the reciprocal's precision. Roots are bit-identical; `agm_dyn` takes 0.97 of its time at 1044 limbs and 0.92 at 16644 (see the reciprocal-carry section of `docs/sqrt_cutoff_tuning.md`). Its knobs (section `sqrt`: `leaf`, the six top-level cutoffs, `dyn_wrapped_rem`, `dyn_rcp_carry`) are read once per call into a `SqrtKnobs`, which the recursion passes down in place of the old `wrapped` argument, and `sqrt_alg(root_len, cutoff)` is the pure predicate for both the top level and a stage; every cutoff, the leaf included, is at least 3, because Zimmermann's split needs a low half. `benches/probes/zimmermann_stages.rs` pastes this file's text (with a `pub use big_bits::{tuning, utils}` shim), so it relies on `zimmerman_sqrt_entry`'s argument list, `SqrtKnobs::dyn_read`, `dyn_div`, `static_div` and `sqrt_denormalization`. The old cutoff probe (`benches/probes/sqrt_cutoffs.rs` and its two scripts) was deleted when sqrt's constants became knobs; it still runs at commit `faa9971`.

- **`verify.rs`** — Linear-time checks of products by their residues mod the NTT primes P1, P2 and P3 (together P ≈ 2^188). `Residues::of(x)` folds x from its low limb up with one Montgomery reduction per limb per prime (r ← limb + r·B⁻¹). One fold is a serial chain of dependent multiplies, so from 128 limbs x is split into four segments per prime, 12 independent chains, recombined by Horner in W = B^seg; powers of B are Montgomery square-and-multiply on B² mod p. `of_with_top` (the entries' (out, returned top limb) convention), `of_limb`, `add`, `sub`, `mul` and `shl_limbs` (times B^k) compose other identities, such as n = q·d + r or x = s² + r; `verify_mul(a, b, c)` and `verify_sqr(a, c)` check c = a·b with c read as an integer of any length. Any error 2^s·E with 0 < |E| < P, such as one wrong FFT coefficient or limb, fails for certain, since 2 is invertible mod each prime; a wider error passes only if it vanishes mod all three at once, and 2^16 has order about 2^56 mod each, so errors don't cancel periodically as they do mod B − 1. It runs at 2.55 ns per limb on the M1, about 8 cycles: each fold step is two multiplies, since the low half of REDC(limb·B + r) is r and its carry is [r ≠ 0], and the four conditional steps per limb per prime are the likely limit. `fft_entry` and `fft_sqr_entry` use it as their residue check. It can't check a middle product's band or a residue mod B^m − 1, which the tests still compare with the NTT.

### Algorithm dispatch in multiplication

There are two dispatch paths, each with different algorithm sets:

**Dynamic path** (`mul_dyn` → `mul_vec`): used by heap-allocated `UBitInt`/`BitInt`.
1. `s == 1` → `mul_prim` (single-limb, asm)
2. `s == 2` → `mul_prim2` (two-limb 128-bit, asm)
3. Small → `mul_buf` (schoolbook, asm inner loop)
4. Medium → Karatsuba (recursive with chunking for unbalanced), while its fitted equation predicts less time than the FFT's (`MulEq`)
5. `output_limbs ≤ FFT_16BIT_CUTOFF` (131066) → FFT (real FFT via `rustfft` on 16-bit digits; in balanced digits; a call reading past `FFT_FOLD_TRIGGER` runs the fold check and is redone on the NTT if that fails, as is one failing its residue check in debug builds or with `FFT_RESIDUE_CHECK`)
6. Large → NTT

**Static path** (`mul_static<N>` → `mul_arr<N>`): used by `UBitIntStatic<N>`/`BitIntStatic<N>`.
Same tiers except FFT is skipped; jumps directly from Karatsuba to NTT.

Squares: `sqr_dyn` is School (`sqr_buf`, ≤ `mul.karatsuba_sqr`) → Karatsuba (`karatsuba_sqr_entry_dyn`, ≤ `mul.fft_sqr`) → FFT (≤ `FFT_SQR_16BIT_CUTOFF` operand limbs, 65533) → NTT, and `sqr_static` School → Karatsuba (≤ `mul.static_ntt_sqr`) → NTT. Both Karatsuba square entries take one level at any length from 6 (at 3 and 5 `karatsuba_sqr_core`'s cross term doesn't fit `out[half..]`) with leaves at `mul.karatsuba_sqr`. High products take `hi_*_buf` up to `DYN_PARTIAL_*_CUTOFF`/`STATIC_PARTIAL_*_CUTOFF` and the guarded truncated product (`hi_mul_guarded_dyn`/`_static`, `hi_sqr_guarded_dyn`/`_static`) above. **`hi_mul_buf` has its own fitted runtime equation** (`HiEq`, knobs `mul.hi_rows_*` and `mul.hi_cols_*`; since 2026-11-12, the user's decision: "Move the tier price in to the mul section"): both of its kernels make the limb products of the window's columns and the two guard columns below it, `hi_window_products(l, s)` = l·s − (s − 2)(s − 3)/2 for a window of l limbs by an operand of s, and differ in what their fixed cost attaches to. The rows kernel (`hi_mul_buf_by_rows`, windows past `mul.hi_mul_row`) is `scale·W + row·s + shift`, a term a limb of the shorter operand (2.9 ns on the M1); the columns kernel (`hi_mul_buf_cols`) is `scale·W + col·l + shift`, a term a limb of the window. Fitted by mul's section on each kernel forced (rows on windows of 12–342 limbs, columns to a third past `mul.hi_mul_row`; the operand from 2 limbs to the window in log scale): 2.7% and 3.8% held out on the M1, where mul_buf's equation on the window's area, which the series' equations read for it until then, was 14.6% (10% low) and 31% (18% low). `HiEq::poly` gives it as a polynomial in the window for sums in closed form. Its readers are the series' equations (`SeriesEnv::hi_ns`); division's NR keeps its own fitted multiple a tier.

`is_school` reads the table knob `mul.kara` (change points over (s, l), with a row index: `tuning::table::Table2`, `school_at`); its default is exactly the old `is_school_at(l, s, 63, 52.0)` boundary (on aarch64 the preset, `presets/aarch64.toml`, replaces it with the table measured on the M1, Karatsuba from 44 limbs for squares and 49 at l = 4s (96 change points; every row from s = 61 is Karatsuba throughout), so tests must find boundaries with `is_school`, never from default values; **measured since 2026-11-12**, `sections::mul::kara_table`: `mul_buf` against `karatsuba_entry_dyn` at each index (s, l), a row at a time in three steps (the square, the near-square shapes to l = 2s − 2, the chunked ones to 4s), each under the rows and steps before it, with the step's own indices Karatsuba's in the live table while they are timed, as the entry asks the table about its own shape first; until then it was derived from fitted equations of schoolbook, one Karatsuba level and chunking, past a margin of their errors, which read Karatsuba from 46 for squares and only from 66 at l = 4s), and `karatsuba_mul` falls back to schoolbook where its scratch is too short, so any valid table is correct. `mul.chunking_karatsuba` and `mul.karatsuba` now only scale `mul_work`, the static series model's product count. Past the table, **dynamic products compare fitted runtime equations per call** (`MulEq`, read once: `dyn_dispatch` → `dyn_large_dispatch`): recursive Karatsuba's `kara_ns` (near-square: `a (l^e − (l − s)^e) + q l s`; chunking, s at most half of l: `a l s^(e−1) + q l s`; e is fixed at log2 3 (`karatsuba_cost`, `chunking_karatsuba_cost`) and the schoolbook weight q is fitted, where an exponent of about 1.63 was fitted until 2026-11-11 (the user's decision: every fit linear in its constants); knobs `mul.kara_rec_*`, `mul.chunk_rec_*`, as `[scale, school]`: a term a limb and a shift were in both forms at first and the timings didn't need them) against the FFT's `fft_ns` at the transform size it really uses (`a ρ(o) N log2 N`, `fft_transform_work` with the fixed per-architecture `FFT_ODD_COST`, `fft_mul_size`; knobs `mul.fft_*`). The cheaper prediction wins, and past the FFT's limit the NTT takes the FFT's place under the same comparison. Those three equations are fitted in mul's second phase, after `mul.kara` is measured, on shapes the table doesn't give to schoolbook (since 2026-11-12: an equation is fitted on the shapes it is read for; on the M1 none are left out, as the fits start at 96 limbs and the table is Karatsuba's from 61), while schoolbook's own equation and `hi_mul_buf`'s are prices inside other equations and keep every shape of theirs. This replaced `is_karatsuba`'s two ratios for `mul_dyn` on 2026-11-11: because the FFT's equation follows its size steps, it loses 0.0–0.2% of measured time against the ratios' 0.2–0.7%, and 0–7% at worst against 8–19% (`cargo tune equations` times both entries over shape grids and reports each rule's loss, and `mul_dyn`'s own, on the same timings). The equations' defaults matter on a target with no preset: Karatsuba's are the M1's fit and `mul.fft_scale` is set so the crossing sits where the old x86-tuned ratio put it. `is_karatsuba` and its float ratios remain for **static** products (`mul.ntt_karatsuba`, `mul.ntt_chunking_karatsuba`; approximate). Its dynamic ratios (`mul.fft_karatsuba`, `mul.fft_chunking_karatsuba`), their two sweeps and `mul_work`'s dynamic tier (`mul_work(l, s)` follows `mul_static`'s tiers alone now) were purged on 2026-11-11, with mul's version 17: no decision had read them since the series' dynamic nodes took fitted equations. The static ratios, `mul.fft_sqr`, `mul.static_ntt_sqr` and `mul.karatsuba_sqr` are sweeps: the tuner times both entries over a grid of shapes (from the main thread, on the global pool) and takes the value with the least measured time lost (on the M1 at mul's version 16: 5.13 and 4.93, 318, about 2800, 69). Squares have one input, so `sqr_dyn`'s Karatsuba-to-FFT cutoff stays a sweep. Every fit is one `nalgebra` SVD solve on relative error (`fit::solve` under `fit_rel` and `fit_split`; an optional dependency of `tune` only, and `levenberg-marquardt` was removed on 2026-11-11, as no equation has a constant inside a power any more); a fit is accepted when its held-out shapes' relative rms is ≤ 5% and no constant solved negative (see "Tuning rules"), and under the old method the equations dispatch reads sat at about 2% (Karatsuba) and 4% (FFT). (The tuner's fits of recursive Karatsuba squares and of the FFT square entry, `mul.kara_sqr_rec_*` and `mul.fft_sqr_m_*`, were purged on 2026-11-10: no decision read them, as `sqr_dyn`'s crossover has one input and is a sweep.) `is_school_at` takes its cutoffs explicitly, as `is_karatsuba` does; its parabola is computed as `1.5 l − l²/(2c)`, the exact expansion of the old `1.125c − (l − 1.5c)²/(2c)`, which cancelled catastrophically for large c (same boundaries at practical c; `mul.karatsuba` ≥ 3 keeps 3×3 on schoolbook, as a Karatsuba level's cross product there is 3×3 again). Every dispatcher has a pure predicate at explicit knobs (invariant 6): `dyn_dispatch_at` (the table and a `MulEq`), `static_dispatch_at` with a `MulKnobs`, `dyn_sqr_dispatch_at`, `static_sqr_dispatch_at`, `hi_alg`, `dyn_mid_dispatch_at`, `static_mid_ntt` and `bnm1_fft_at`. Neither formula fits the measured boundary shape by shape (see `docs/mul_cutoff_tuning.md`, which also proposes a refit of `is_school`), so their constants minimize the mean time lost over a grid of shapes.

The cutoffs were retuned after the row-wise schoolbook kernels with `benches/mul_cutoffs.rs` (deleted 2026-11-08, when they became knobs; it still runs at commit `faa9971`), which forces each side through the library's own entries (`karatsuba_core`, `chunking_karatsuba`, `karatsuba_sqr_entry_dyn`, the guarded high products, `hi_*_buf_cols`/`hi_*_buf_by_rows`, and the transform entries), and `benches/mul_cutoffs.py`, which builds three code layouts, runs pinned (or, for the static NTT families, all-threads) processes and analyzes them. Nanosecond-scale crossovers get 24 processes and an exact Wilcoxon test per shape; microsecond-scale ones a few processes and averages (`--simple`). Karatsuba's own cutoffs are measured on a build whose leaves are schoolbook (`build --set ...`), then once more at the result. See `docs/mul_cutoff_tuning.md`.

### NTT implementation

NTT uses Montgomery modular arithmetic over three NTT-friendly primes (P1, P2, P3 in `mul.rs`), then reconstructs the true product via CRT. This avoids precision loss for large multiplications.

Twiddle factor tables come in two variants:
- `StaticNTTTwidles<N, P>` — compile-time fixed size, used by the static path
- `DynNTTTwidles<P>` — runtime-computed, cached in thread-local `HashMap<usize, DynNTTTwidles<P>>`

NTT supports radix-2, radix-3, and radix-5 butterflies to handle transform sizes that are smooth 5-smooth numbers.

**Previously-known source bugs, now fixed**:
- `karatsuba_entry_dyn`'s chunking path panic (`lhs must be longer then rhs` from `add_buf`) — **fixed**. Root cause: `chunking_karatsuba`'s last-chunk remainder can be up to `2*short.len()-2` limbs, landing at the exact Chunking/Recurse dispatch ratio boundary. The resulting `karatsuba_core` call needs its output buffer to be `>= 3*half+1` limbs (`half = ⌈a.len()/2⌉`) for its cross-term reconstruction (`add_buf(&mut out[half..], &cross)`), which exceeds the standard `a.len()+b.len()-1` sizing convention by 1-2 limbs whenever `b.len()` is only just above `half` — a generic gap in `karatsuba_core`'s Recurse path, not specific to chunking. Originally fixed by redirecting through a `3*half+1` scratch buffer. The current `karatsuba_core` instead adds the part of `cross` that fits in `out[half..]` and folds its carry and the first omitted limb into the one legitimate overflow limb (higher omitted limbs are provably zero by the a.len()+b.len() product-size bound), so `find_karatsuba_scratch` reserves no extra space for it. Fixing this exposed a second, independent, previously-latent bug: `karatsuba_mul`'s `Prim`/`Prim2` dispatch arms called `mul_prim`/`mul_prim2` on the *full* `out` slice rather than truncating to `long.len()`, so any caller passing a wider `out` (which the sizing fix above newly does, for nested `a1×b1` sub-calls) fed whatever stale scratch-pool garbage sat beyond `long.len()` into the multiply as if it were part of the multiplicand — silent corruption, not a panic, and only reachable when the scratch pool happened to hold nonzero leftover data from an earlier call. Fixed by truncating to `long.len()` before the multiply and explicitly zero-filling/folding any excess. Regression tests: `test_karatsuba_entry_unbalanced`, `test_karatsuba_core_recurse_boundary_sizing` (engineers the exact last-chunk boundary ratio), `test_karatsuba_entry_unbalanced_random_sweep`, `test_karatsuba_mul_prim_dispatch_ignores_stale_out_tail` (poisons `out`'s tail explicitly). Verified via an independent Python differential-fuzz model (tens of thousands of trials) before porting to Rust — worth doing again for any future change near `karatsuba_core`'s buffer arithmetic, since two of these three bugs produced *silently wrong results*, not panics, and are easy to reintroduce with a plausible-looking size-only fix.
- `powi_dyn_entry(&[3], 0, &mut out)` — **fixed**. Root cause confirmed: `powi_sz` returned `(0, 0)` for `pow == 0`, so callers allocated an empty output and `powi_dyn_entry`'s `out[0] = 1` indexed out of bounds. Fix: `powi_sz` special-cases `pow == 0` to return `(1, 1)`.
- `powi_dyn_entry(&[3], 1, &mut out)` — **fixed**. Root cause was more precise than "one step too high": bit 0 of `reverse_pow(pow)` was *always* 1 for every `pow` (an artifact of `pow`'s own leading bit leaking into the construction), forcing an unwanted multiply on the first step of every call, with the real exponent bits all landing one position higher than intended. Fixed by rebuilding `reverse_pow` directly from `pow`'s rest-bits (`pow - (1 << pow.ilog2())`) reversed into a `k`-bit field with a sentinel at position `k`, instead of the old shift-and-reverse-all-64-bits trick. This changes how many src/dst swaps `powi_dyn_core`/`powi_static_core` perform, so the parity check in `powi_dyn_entry`/`powi_static_entry` that decides which buffer starts as the answer flipped too (`% 2 == 0` → `% 2 == 1`) — the two changes only work together. Verified exhaustively (`test_powi_dyn_entry_small_exponents_exhaustive`) against a repeated-multiplication oracle across every exponent bit-length/popcount combination up to 20.
- Static `bin_split` nodes panicking at large leaf cutoffs (`StaticNodeBBP`'s "a leaf's P and Q * 2^(shift * terms) must fit N limbs" assert; an index-out-of-bounds in `push` for `StaticNodeEngel`/`StaticNodeHyper`) — **fixed**. Root cause: static merges drop low limbs to stay within `N` (`hi_mul_drop`), but leaves build some products exactly into `[u64; N]`. These are BBP's P and `Q * 2^(shift * terms)`, which must share a scale because its node has no exponents, plus Engel's Q and Hyper's Q, and also Hyper's R when x = 1. A leaf whose range was too large for `N` overflowed, so whether a cutoff worked depended on `N`, the leaf's position and the series, even though every cutoff is mathematically valid. Fixed without touching the kernels, node layouts, `Node` trait or `bin_split_tree`: each static `leaf` checks a conservative bit-length bound (`leaf_fits`, using `prod_fits`, which relies on `bitlen(xy) <= bitlen(x) + bitlen(y)`) and, when the bound fails, splits at the midpoint and merges. Leaves therefore stay exact and only merges drop limbs, the same as a smaller cutoff. The exact-leaf bodies are `#[inline(never)]` so the recursive frames don't carry unused `[u64; N]` buffers. Static parts now have bit exponents and BBP's Q no longer carries the shift, so a single BBP term always fits (`test_static_bbp_shift_past_n`). Regression tests: `test_static_large_leaf_regressions` (the exact panicking leaves), `test_static_nodes_any_cutoff` (single-term leaves, two-term leaves, the default cutoffs and single-leaf `u64::MAX` limbs at N = 4–64), `test_static_leaf_size_sweep` (every single-leaf size through and past the bound, so a bound that undercounts panics right at the boundary). The old tests missed this because they only built deep trees with small leaves.
- `karatsuba_core` silently wrong products (`mul_dyn`, `mul_static`, `karatsuba_entry_*`, and therefore `hi_mul_dyn`) — **fixed**. Root cause: `karatsuba_mul(a1, b1, z2)` returns the product limb at index `z2.len()`, but the cross-term correction subtracted it at `cross[buf_len(z2)..]`, which is lower whenever z2's top limb is zero. The squaring twin `karatsuba_sqr_core` already used `z2.len()`. Triggers: both operands with an all-zero low half (e.g. `[0; 20] + [1 << 58]` squared, at sizes ≥ 19), and structured real operands whose sub-products land a zero top limb deep in the recursion (found via `ratio_to_fraction_dyn` → `hi_mul_dyn` in `exp_dyn`). Random operands almost never hit it (probability ~2^-64 per sub-product), so every random-data test passed. Regression tests: `test_karatsuba_core_overflow_offset_zero_top`, `test_karatsuba_structured_operands` (embedded 151×151 pair), and `test_mul_structured_operand_fuzz`, which biases limbs toward zeros and powers of two and caught 571 bad products in 6000 trials with the old offset. Oracles for big-number tests should use schoolbook `mul_buf`, not `mul_dyn`.
- `hi_sqr_buf(&[], ..)` subtract-with-overflow panic — **fixed** with an empty-input guard matching `hi_mul_buf`. `test_karatsuba_static_chunking_scratch_fallback` also asserted a stale `find_karatsuba_scratch(150, 50) > 199` left over from the scratch-redirect design; the true requirement is 178, and the test now uses `N = 177` so the static fallback actually runs.
- `rcp_dyn`/`rcp_static` (NR path) breaking the `< B` error contract from `R = 727` (multi-limb errors, growing with `R`; first `R ≡ 7 mod 8`, then most sizes past ~1450) — **fixed**. Root cause was in `hi_mul_dyn`/`hi_mul_static` (and the `hi_sqr_*` twins), not the Newton code: above `PARTIAL_MUL_CUTOFF` they truncated each operand to exactly `out.len()` limbs, and the dropped partial products are worth up to ~2B ulps, i.e. the whole low output limb was wrong (`hi_mul_buf` is within a few ulps). A Newton step squares its input error, so one untruncated refine step (`q` even) with `p > 90` injected ~B ulps that grew 1 → 2 → 4 → 8 limbs over the remaining steps and outran the two guard limbs; odd `q` steps drop the correction's low limb and hid it, hence the `R`-parity pattern. Fixed by keeping `HI_MUL_GUARD_LIMBS = 2` operand limbs below the window (≤ 1 ulp error). The core product stays at its old unguarded size and `add_hi_guard_terms` adds the guard limbs' terms with linear `add_mul` passes, because simply widening the core can push it past an FFT/NTT transform size (measured up to ~2× slower at power-of-two `n`). Static entries clamp the guard (`hi_mul_static_guard`) so the split paths' low buffers still fit `N`; since operands have at most `N` limbs, the clamped guard still keeps them whole from `out.len() = N - 1`, so those windows are exact. Cost: ≈ +1–4% on `hi_mul_*`/`hi_sqr_*`, ≈ +0–1% on `rcp_dyn`/`div_dyn` at most sizes. Regression tests: `test_nr_reciprocal_high_precision_regressions`, `test_nr_reciprocal_static_high_precision_regressions`, `test_hi_mul_truncation_error_is_a_few_ulps` (the old test tolerated a fully wrong low limb, which is how this slipped through), `test_hi_mul_guard_terms_match_exact_window`, `test_hi_mul_static_near_capacity`.
- `hi_mul_static` panicking (`range end index N + 1 out of range`) at `out.len() == N` with two `N`-limb operands, even `N` — **fixed**. Root cause: the split path computed its `l1 * s0` cross term into `tmp2[..l1.len() + s0.len()]`, and for even `out.len() = N` the window width `k = N + 1` is odd, so `l1` gets one more limb than `s1` and `l1.len() + s0.len() = short.len() + 1 = N + 1`. Fixed by keeping that product's top limb out of the buffer and adding it into `out` separately, as the `l0 * s1` term already did. The guard clamp had a second term (`N - out.len() - 1`) that only existed to dodge this overflow, and it left `out.len() = N - 1` with no guard at all (a whole wrong low limb, the same bug as above); dropping it makes that window exact. `bin_split`'s static merges (`hi_mul_from`) call `hi_mul_static` with up to `N` output limbs, which rely on those exact windows. Regression test: `test_hi_mul_static_near_capacity` (`N` ∈ {96, 97, 160, 161, 512}, `out.len()` from `N - 4` to `N`, requires exact windows at `N - 1` and `N`).
- `div_dyn`/`div_static` (NR path) returning a quotient one too small — **fixed**. Root cause: `nr_refine_quo` measures err = d·y − n with a middle product, which drops the carries from the product's columns below the band: up to about (h + 1)·B at its base (the school middle product adds back only the column just below; the dyn FFT/NTT and static NTT ones drop them all). The band used the raw top window of d, so turning it into quotient units scaled that carry by B / (d's top limb), and at an odd quotient width (q_len − 2h = −1) the band's base lines up with the estimate's top guard limb, which the `Exact` verdict trusts. An exact division by a divisor with top limb 0xb came out 9·B⁻¹ low, its guard limb read u64::MAX − 8, and NR returned that floor without correcting it. Fixed by forming the band from the normalized windows of d·2^sh and n·2^sh, and the correction from the reciprocal of d·2^sh before its shift (x_norm·err_norm = x·err), which bounds the dropped carry at about 2(h + 1) ulps of the second guard limb. `div_rem` was unaffected, as its windowed finish always corrects. No measurable cost. Regression test: `test_nr_exact_division_small_top_divisor` (exact divisions with divisor top limbs 1 to 2^20 at odd quotient widths 9–739, dyn and static, including the static NTT middle product from h + 1 = 200). Before the fix, half of its cases from q_len = 201 failed.
- `ntt_mid_mul_dyn`/`ntt_mid_mul_static` returning limb 1 off by about 2^60 — **fixed**. Root cause: `ntt_mid_accumulate_scaled` reads the two convolution coefficients below the band (`res2[lo-1]`, `res3[lo-2]`), and each prime's transform was sized for `2n-1` coefficients, which wraps the product's top columns (up to `3n-3`) onto exactly those two. Where the three primes picked the same size the wrap was consistent and only disturbed limb 0, but where `2n-1` was an NTT size for some primes and not others (2n − 1 = 81, 125, 243, 375, 405, 625, 1125, 1215 below n = 700), the CRT combined residues that disagreed. Fixed by sizing every prime's transform for `2n+1` coefficients (`mid_ntt_size`), as `fft_mid_mul` already did, so nothing wraps onto a coefficient the accumulation reads. The largest transform grows at about 1% of sizes from 672 to 4096 limbs, by at most 8%. Regression test: `test_ntt_mid_mul_exact_size_transform` (those n, dyn and static, plus the static zero-padded path). Every n from 3 to 1500 is now within the documented error.
- Wrong products, squares and middle products from the 16-bit FFT inside its old bounds — **fixed**. Root cause: f64 precision, not an arithmetic bug. A coefficient of an l × s product sums up to 4·min(l, s) products of 16-bit digits, about 2^34·min(l, s), leaving only a few bits of a double for the transform's rounding, and unsigned digits near their maximum put nearly all of it in the zero-frequency term. `FFT_16BIT_CUTOFF` (2^16 output limbs) had been checked only with random operands, which round 3–4× better, and `dyn_sqr_dispatch` compared it with the square's operand length, twice the product's reach. Against the NTT, all-ones squares were wrong from 23814 limbs, all-ones products from 26460 × 26460, and worst-case middle products from about n = 16800. The library's real FFT also loses up to about a bit against plain rustfft at mixed-radix sizes (not the twiddle tables, which were checked exactly; probably the real-FFT packing). First fixed by per-entry bounds just below the first transform size where 10000 worst-case operands gave a wrong limb (36863 output limbs, 18000, 16799 and 23040), which kept on moving down as the search grew. Then fixed by a round-off check (redo past 0.4 or a 2^48 coefficient, as past 2^48 a coefficient's error comes in steps of ulp(N·c)/N, coarse enough that 264 wrong results read 0.375 or 0.25), and now by balanced digits and a fold check past 0.25, with residues in debug builds (131066 output limbs, 65533, 65533 and 57344 are the limits now). `docs/fft_precision.md` has the searches and soundness runs. Regression tests: `test_fft_fold_check_catches_wrong_results`, `test_fft_checked_entries_stop_past_their_limits`, `test_fft_residue_check_catches_wrong_results`, `test_dyn_dispatch_exact_around_fft_limits`, `test_sqr_mod_bnm1_large_against_full_square`, and the feature-gated `test_fft_fold_check_with_many_worst_case_operands`.
- `div_dyn`/`div_static`/`hi_div_*` (NR path) returning a quotient one too large, and `div_rem_dyn`/`div_rem_static` returning q·d + r ≠ n — **fixed**. Both were in how `nr_refine_quo` applies its correction c = x_norm·err to the estimate y. When err > 0 the floor of y − c is y − ⌈c⌉, but it subtracted ⌊c⌋, one too little whenever c has a fraction. That needs y's own rounding to make err positive: a true quotient with an all-ones run of limbs just below the cut (with a random d, 73–88% wrong from 4 limbs and 9–13% at 3), or an all-ones d under a mostly-ones n. `div_rem` escaped this one, as its finish always corrects. When err < 0, subtracting x_norm's top limbs could leave a tiny positive c, because x_norm's limbs below k aren't subtracted. Negating that gave nearly all ones, and c is narrower than q, so q came out off by about B^(k − 2) with no wrap. `nr_rem_finish` reads only the low d.len() + 1 limbs, so it can accept that when d has zero limbs, as in n = (d·m)·B^k + small; `div_dyn` escaped this one, as its full product fails and it retries BZ. Fixed by reading c's sign after the subtraction, and by `dec_buf` after the subtraction in the positive branch; a c with no fraction reads guard limb 0, so correction restores the extra 1. No measurable cost (0.996–1.002× on forced NR from 128 to 4096 limbs). Random operands reach neither bug, so the whole suite passed with both. A differential fuzz of the dyn, static, forced NR and high entries against forced Knuth on structured operands gave 7646 wrong results in 40000 shapes before the fix, and failures as large as d = 16378 in a further 320; after it, none in 400000 shapes up to about 2000 limbs or in 1200 from 2000 to 16384. Regression tests: `test_nr_quotient_floor_when_estimate_rounds_up`, `test_nr_rem_scaled_multiple_of_sparse_divisor`.

### Tuning rules (the user's decisions, 2026-11-10)

- **One input: a sweep. Several inputs: fitted runtime equations.** A decision governed by one number (a cutoff, a gate, a balance point) is measured directly. A dispatcher over two or more inputs (products, divisions) compares runtime equations in each algorithm's theoretical form, with constants fitted to that algorithm's own timings. Never derive a runtime purely from other algorithms' models; an equation may include another's fitted time (a Karatsuba level includes its sub-products' schoolbook time).
- **A fit is accepted at relative rms ≤ 5%** (`fit::ACCEPT_RMS`), read on the shapes it didn't fit (`Fit::judged`: the held-out rms; the user's decision, 2026-11-11), with the fitted shapes' rms reported beside it. The worst single residual is reported and never judged. For a sweep, a level's thoroughness is its samples' spread bound, (interquartile range)/median: 6% quick, 4% normal, 2% thorough (1% made a thorough tune take 36 minutes with 10% of measurements never settling); for a fit it is the number of shapes (`Level::fit_shapes`: 1, 2 and 4 times the quick count).
- **How a fit is found: one way, everywhere** (the user's decisions, 2026-11-11; plan `~/.claude/plans/come-up-with-a-dapper-minsky.md`; mul's, div's and the series' fits are all on it). Effort goes into more shapes, not into a tighter time at each: a fit pools its shapes, so its constants' error falls with their number. (1) *Shapes*: scattered over the two-dimensional area where the algorithm competes (`tuner/design.rs`: `scatter`, the R2 low-discrepancy sequence in log scale; `products` for (l, s); division's (q, d); the series' (frame, chunk position)), not along a few fixed ratios or frames, and every other one held out. A report that judges live equations takes its points far along the same sequence (`design::UNSEEN`), so they are none of any tune's. (2) *Timing* (`measure::time_fit`): a fixed three batches of every probe and no spread bound, taken in rounds that each visit every probe once in a shuffled order, the whole set twice with its buffers moved; a probe's time in a pass is the median of its batches, the value is the least of the two passes, and their difference is the noise (`pass_noise`, in each fit's evidence as "passes differ", and over a whole tune on the "fit probes" line, which warns above 5%). The rounds are there for a reason found by trying without them: batches taken back to back lost all three of a probe's batches to one disturbance of a few milliseconds, and 5–7% of a tune's first fit's probes read up to 2.4x slow in one pass. (3) *Solve*: `nalgebra`'s SVD on relative error (`fit::solve`), which also gives each constant's standard error and the design's condition number; `fit_split` solves without the held-out shapes for the rms the 5% line reads, then on all of them for the constants written. (4) *A term that solves negative isn't needed* (the user's words): it is left out at 0 and the rest solved again (`solve_nonneg`), and the fit's evidence names it with the value it solved; it rejects nothing. (5) *Which terms a form needs is the developer's question, never a tune's*: `cargo tune tune --analyze` prints, for each fit, every constant solved freely against its standard error and its share of the predicted time, and the best form of each size that solves with no negative constant, by its held-out rms (`fit::analysis`). A tune only ever fits the form the equation has; changing an equation's terms is still the user's call. Every equation is linear in its constants: recursive Karatsuba's fitted exponent became a schoolbook term with its own weight, and `levenberg-marquardt` is gone. **The forms were then trimmed and the M1 preset retuned (2026-11-11, the user's go-ahead).** The 15 constants the analysis found unneeded are out of the equations, schema and tuner, not left at 0: schoolbook's term a row; the Karatsuba level's term a limb; chunking's shift; recursive Karatsuba's and recursive chunking's terms a limb and shifts; the FFT's term a point and shift; NR's term in d and shift; NR with remainder's shift; BZ's term in q; the series Horner's fixed cost and binary splitting's price for one-limb multiplier passes (mul is at version 17, div at 8, series at 3; the schema's defaults for those equations are the M1's new fit). The preset is `presets/aarch64-macos.toml`, thorough, 1503 s with the gate, which kept all 9 sections (each within 0.3% of the values before it on its workloads). Held-out rms: schoolbook 3.9%, Karatsuba level 2.0%, chunking 2.5%, recursive Karatsuba 2.6% and chunking 1.6%, FFT 3.6%, Knuth 2.2%, NR 3.1% and 3.8% with remainder, BZ 2.9%, and the series' Horner 7.0%, rect 11.6% and binary splitting 8.6% (NOISY, as before); no term solved negative. 8354 fit probes whose passes differ 2.8%. The sweeps' "samples" line read 5.9% unsettled, past its 5% warning (it reads 4.8-5.05% at thorough on a steady machine; this run was on battery, 51% to 35%), which is the one caution on this preset. Picks on shapes the equations never saw, under the preset: products 0.00% of measured time lost; `div_dyn` 0.07% (worst 4.9%) and `div_rem_dyn` 0.30% (worst 13.2%), against 0.01% and 0.15% for the preset before on its own half-step grid; series 0.24% and 0.62% on the two halves of an unseen set (worst 11.7%). NR quotient-only is the one fit the trim cost: 2.2% held out with its shift and a normal-level schoolbook equation that had a term a row, 3.1% now. The first full run before the trim (normal level, to a scratch file) and its form analysis are in `docs/tuning_implementation.md` ("One way to fit").
- **Only what a decision reads is measured.** A fit or benchmark that no dispatcher's decision depends on is purged from the tuner, the schema, the docs and the plan. A procedure used in tuning only one algorithm is fitted as part of that algorithm, never measured separately (chunking Karatsuba had its own fit, `mul.chunk_*`, which went with the Karatsuba level's on 2026-11-12: they were read only to derive `mul.kara`, which is measured now). `base`'s cost units, `model.rs`, `dispatch.rs` and `threads.rs` were removed under this rule.
- **Tune a helper through its callers.** bin_split's two parallel gates are swept through whole `exp_dyn` and `ln_dyn_at` calls, not isolated trees: started from the main thread a parallel split has to wake the pool, and on isolated trees the split gate read 1024, which made `exp_dyn` and `ln_dyn` 3-5% slower. Its dynamic leaf cutoffs are swept on their own trees and on those calls together (2026-11-10): on exp's and ln 2's trees alone the Hyper leaf read 192 limbs where ln's atanh chunks want about 48, and `ln_dyn` at 300 and 500 limbs ran 7% and 11% slower, which the tune's end-to-end gate listed. The NTT's four gates are swept through the NTT entries (dynamic at 70000 limbs, static at about 3000).

- **Parallel algorithms.** A tune runs at the thread count the code will be used at. The tuner finds each thread-dependent value for a serial version and a fully parallel version, and the library chooses between them at run time (not built yet). - **Static algorithms get approximate values only** (the user's decision, 2026-11-11: their memory handling is about to change fundamentally). - **Every tune ends each section with the end-to-end gate, and any checkout can tune itself** (the user's decisions, 2026-11-10). After a section is measured, `tuner/check.rs` times the workloads of that section and of every section built on it (`tuner/check_items.rs`, the 201 items shared with `benches/tuning_bias.rs`) under the values before it and after it, in paired rounds in one process. The section is dropped, its values and the file going back, when the mean is slower by more than the gate's allowance, 3% at quick, 2% at normal and 1% at thorough (`Level::gate`: the user's numbers, wider than the sweeps' tie band so that noise from one tune to the next doesn't reject a section), with a 95% interval that excludes 1, or when an exact output differs. A single workload more than 2% slower is listed and never drops anything: read that list, as a regression concentrated in a few workloads passes on the mean (it is how the Hyper leaf's 7–11% on `ln_dyn` was found). The tuner has no steadiness preflight (the user's decision); the FFT's odd-part factors stay hard-coded per architecture, x86's still to be measured on the i7.
- **Sweeps keep a value inside the tie band.** A sweep replaces a knob's value only when another loses less mean time by more than the level's ε (3% quick, 1% normal, 0.5% thorough; `Level::eps`, applied by `sweep::keep_or_take`, the one place the rule and its evidence are written); otherwise its evidence says "kept". Knobs that interact (bin_split's leaves and its split gate) are swept twice, each under the values before it. Each measurement also has a time budget per pass (`Level::probe_budget_ns`).
- **Whole-algorithm sweeps are judged by stability, not spread** (the user's decision, 2026-11-11). A sweep that times whole trees or whole `exp`/`ln` calls (`param_sweep`, `cutoff_sweep_whole`) takes a fixed number of samples twice and accepts its choice only when both measurements support it within the tie band; otherwise it keeps the previous value and says UNSTABLE. They also use few workloads and candidates. The spread bound still governs kernel measurements and fits. `ln.*_chunk_min_bits` (2) and `ln.*_sqrt_a` (0.25) are deliberately left at their defaults and unswept: their best values differ by size, and a different square-root scale also moves the series-against-AGM cutoff (0.5 moved it from 32 limbs to 1024), so sweeping it made the whole ln section flip from run to run.

- **A dispatcher's table is measured, and one rule says where it has one** (2026-11-12, the user's decisions: "The table should be reworked and derived from actual measurments at each index size instead of the table being derived from the fits. ### Compile-time constraints

Avoid `u128` arithmetic in `const fn` contexts — it significantly increases compile times. Use `u64` or split operations instead.

### Feature flags

- `_bench_internals` — exposes internal `utils` functions for Criterion benchmarks; do not use in non-bench code
- `_fft_cutoffs` — gates FFT-specific cutoff paths (used during cutoff-tuning benchmarks)
- `tune` — the tuner (`src/tuning/tuner/`, run by `cargo tune` through `examples/tune.rs`), and knob accessors read live atomics that `tuning::set`/`apply` change (for the tuner and the random-knob test only; normal builds read constants). Never change a knob while a library call runs. In a tune build the crate also names itself `big_bits` (`extern crate self`), so `tuner/check_items.rs`, the end-to-end check's workloads, and `tuner/synth.rs`, the synthetic series, are files the tuner and `benches/tuning_bias.rs` both include
- `build.rs` generates `$OUT_DIR/tuning.rs` (accessors `k::<section>::<knob>()`, `resolved::` constants) from `src/tuning/schema.rs`; it reruns only when `build.rs`, `build/`, the shared `src/tuning` files, `presets/` or `BIGBITS_TUNING` change. Layers, lowest first: the schema's defaults, the target's preset (`presets/<arch>-<os>.toml`, else `<arch>.toml`), then the machine's own file, the one `BIGBITS_TUNING` names (`presets/local.toml` in a checkout, through `.cargo/config.toml`'s `[env]`). A file whose `[meta] target` isn't the build's is skipped with a warning (`resolve::layer_target_ok`), a set-but-missing path outside `presets/` warns, and a section set by several layers has only the top layer's upstream record checked
